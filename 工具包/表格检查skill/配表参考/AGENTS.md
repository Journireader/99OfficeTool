# AGENTS.md

本目录用于帮助 AI 和配表人员按需理解 FF 配置，而不是让使用者先通读整个知识库。上层 `../AGENTS.md` 的源表环境、SVN、锁、写入、验收和提交规则继续生效；本文件只补充“如何检索、如何对齐理解、何时才可以开始配”。

## 核心顺序

任何配置任务都按下面顺序推进：

1. 按需检索并确认当前事实。
2. 把用户原话、已验证事实、AI 自行补出的理解和仍有影响的歧义分开说明。
3. 对齐目标、配置对象、业务含义和可见结果。
4. 用户确认后形成精确配置方案。
5. 另有明确源表写入授权后，才执行配表、读回和验收。

只读查询可以直接进行；查询结果不能自动变成设计决定，设计决定也不能自动变成源表写入授权。

## 按需检索

收到表名、Sheet、字段、ID、系统名或自然语言需求后，不要全量读取本目录。按以下路径只读取命中内容：

1. `README.md`：入口、证据边界和通用使用规则。
2. `约定/速查表.md`：按任务关键词初步定位。
3. `约定/表到专题索引.md`：定位 workbook、第一参考、事实卡和联查方向。
4. 命中的 `事实卡/*.md`：字段语义、常见误判、反向影响和最小验收。
5. 命中的 `系统/*.md`：多 Sheet、跨表关系、配置顺序和系统规则。
6. 只有进入字段、数组展开、主键或结构判断时，再读 `约定/表字段索引.md`。
7. 最后回源 Excel 读当前 workbook、Sheet、字段和目标行；参考文档不能替代源表当前值。

若参考状态是 `已验证导航`，只能证明入口存在，不能证明字段和业务语义已经补全。`部分确认`、`需确认`、`待补`、`历史` 以及未写明的规则都不得作为确定配置结论。

## 理解对齐

开始制定配置结果前，先用简短、可回答的方式亮出本次理解：

- **用户明确提出的**：目标和已说清的要求。
- **当前查到的**：源表、Sheet、字段、现值、引用关系和已验证消费者。
- **AI 自行补出的**：用户没有明确说、但本方案需要采用的业务含义、范围、默认值或结果取舍。
- **仍需确认的**：不同答案会改变玩家结果、写入范围或验收方式的问题。

可从源表、当前参考或消费者查清的事实由 AI 自行查，不反问用户。只有会改变结果且无法从现有责任源裁决的歧义才询问；问题按影响排序，每个问题给出推荐理解及其影响，让用户能直接确认或纠正。

只要“AI 自行补出的”清单非空，或用户正在回答的问题是配置方案的前提，就停在理解对齐，不制作配置结果、不写源表。用户确认过的内容不重复询问；用户纠正后，以最新说法重算受影响的配置和联查范围。

## 开始配表的条件

进入配置方案前，至少应明确：

- 目标环境：默认 `develop`；`beta`、`release` 或其他环境必须明说。
- 目标 workbook、Sheet、主键／分组键以及目标 ID 或行。
- 每项字段的业务含义、单位、空值／0 值语义和数组展开方式。
- 期望的玩家可见结果或系统行为。
- 必要的文案、条件、入口、奖励、物品、随机池、资源、商业化等关联表。
- 哪些是已确认决定，哪些仍是待校准假设或程序前置。

配置方案至少给出 `before → after`、关联影响、验证方法和精确写集。缺少统一数值责任源时，不替用户决定公式或数值，只保留显式待确认项。

源表写入还需要用户明确授权“录入、回填、填进去、改表”等实际写入动作。只有“看看、分析、给方案、怎么配、继续研究”时保持只读。写入后的锁、最小差异、读回、结构校验和提交规则沿用上层 `../AGENTS.md`；写入授权不等于提交授权。

## 输出要求

查询或对齐结果优先直接回答业务问题，并给出精确的 workbook、Sheet、字段和 ID。必要时补充：

- 已验证事实；
- 已确认决定；
- 合理推断或候选；
- 尚未验证的程序生效、线上状态或业务规则。

不要因为表里存在字段就宣称程序已消费，也不要因为代码存在消费者就宣称运行环境已经生效。

## 参考回补

检索或配表中发现稳定的新事实、旧结论错误、字段／Sheet 结构变化或新的高频误判时，回补已有事实卡或系统专题，并同步 `README.md` 与 `约定/表到专题索引.md`。单次任务过程、未确认设计和临时结论不写入本目录。
