## 0. 元信息

- 事实源：`develop/system/Ad.xlsx#AdScene`
- 最近验证：2026-09-21 / SVN r6595 / Excel 全量读回；proto `0e483c70a630`；server `f5bb1bc2f786`
- 状态：已验证表结构、广告服务计数与通用发奖路径；各业务场景自己的收益逻辑按具体系统继续核对
- 适用范围：广告场景开关、自然日次数、触发间隔、通用广告奖励
- 禁止推断：`Ad.xlsx` 行存在不代表业务入口一定展示；空 `Loots` 不代表场景没有业务收益；`PurchaseID` 当前未见广告服务消费

## 2. 字段语义

| 字段 | 语义 | 空值 / 0 | 单位 / 引用 | 易误判 |
|---|---|---|---|---|
| `AdScene` | 广告业务场景主键 | 0 是无效枚举，不作为业务行 | `AD_SCENE` | 中文枚举展示不是自由文本，不能自造 |
| `AdSwitch` | 通用广告服务开关 | 0 关闭；关闭时服务端不返回可用信息并清理该场景计数记录 | 0/1 | 不等同于业务入口总开关，业务模块还可能有自己的条件 |
| `DailyCountLimit` | 自然日可成功领取次数上限 | `<=0` 按关闭处理 | 次/自然日 | 当前重置按服务器自然日，不是滚动 24 小时 |
| `TriggerInterval` | 两次成功广告领取之间的最短间隔 | 0 表示无额外等待 | 秒 | 服务端返回的 `NextAdTime` 是 Unix 时间点，不是剩余秒数 |
| `Loots#N.PropType/PropID/Value` | 通用 `GetAdReward` 接口发放的奖励数组 | 整组空表示通用接口不直接发奖励 | 奖励三元组 | 现有 8 行全部为空；具体玩法可能在自己的业务接口给收益 |
| `PurchaseID` | 协议保留的小额支付商品 ID | 空表示未配置 | 应关联 `commerce/PurchaseList.xlsx#PurchaseList.PurchaseID` | 当前广告服务计数与发奖路径未读取此字段，不能仅填表宣称生效 |

## 3. 运行顺序

1. 客户端请求一个或多个场景的广告信息。
2. 服务端过滤掉无配置、`AdSwitch=0` 或 `DailyCountLimit<=0` 的场景。
3. 对有效场景返回已用次数、最大次数和下一次可用时间；自然日变化时次数清零。
4. 领取时再次检查剩余次数与 `TriggerInterval`，通过后次数加一并记录时间。
5. 通用领取接口只按本行 `Loots` 发奖；业务场景的额外效果必须回到对应系统核对。

## 4. 跨表与反查

| 改动 | 必查 |
|---|---|
| 新增 `AdScene` | 先确认 proto 枚举已有该值，再确认服务端上报映射和业务入口消费者；没有枚举时是程序前置 |
| 改次数 / 间隔 | 对应业务入口展示、按钮冷却、自然日刷新；测试 0、1、上限值和间隔边界 |
| 配 `Loots` | `PropType` 分流到资源枚举或 `Item.ItemID`；验证通用广告领取接口不会与业务接口重复发奖 |
| 配 `PurchaseID` | `PurchaseList.PurchaseID` 命中；当前还需补消费者证据，不能只做表侧回填 |
| 删除 / 关闭场景 | 反查业务模块是否仍显示入口；服务端会清理该场景已有广告计数记录 |

## 5. 常见误配

- 把 `DailyCountLimit=0` 当“无限次”；当前实现把它当不可用。
- 把 `TriggerInterval` 填成毫秒。
- 看到 `Loots` 为空就判断广告没有收益，或在 `Loots` 补奖却没有排查业务侧重复发放。
- 用 Excel 中文显示文本新造广告场景，而没有对应 `AD_SCENE` 枚举。
- 填了 `PurchaseID` 就认定小额支付替代链已经接入。

## 6. 最小验收

- `AdScene` 唯一且能映射 `AD_SCENE`；业务场景入口存在当前消费者。
- 开关、每日次数、间隔分别测试关闭、首次、间隔内、达到上限、次日刷新。
- `Loots` 非空时完成奖励三元组引用检查，并验证不重复发奖。
- `PurchaseID` 非空时既命中商品表，又有当前广告链消费者证据。
