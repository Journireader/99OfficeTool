# I18N 配表经验

## 核心原则

I18N.xlsx 不是一张表，是按业务拆成几十个 sheet。每个业务系统的展示文案由各自的 I18N sheet 管理，不要混。

**技能表只有基础版技能才配 I18N#Skill。** 铭文变体、圣物被动、词缀被动都不配 I18N#Skill——它们的展示文案分别走 I18N#Inscription、I18N#Relic、I18N#Affix。

运行时加载不是只按本文列出的固定 sheet 清单读取。客户端会从配置 MD5 表中扫描所有 `I18N#` 开头的配置 key，动态加入 required config，并合并到 I18N 运行仓库。本文的 sheet 清单用于配表路由和归属判断，不代表运行时唯一加载名单。

## I18N 归属速查

| 业务 | 展示文案来源 | I18N sheet |
|------|-------------|-----------|
| 基础版技能（C=0, D=0） | Skill.Name / Describe / Keyword | I18N#Skill |
| 铭文变体技能（C≠0 或 D≠0） | 不配 I18N | 玩家看铭文描述，不看技能描述 |
| 铭文 | Inscription.Name / Describe | I18N#Inscription |
| Buff | Buff.Name / Describe | I18N#Buff |
| 词缀 | Affix.Name / Describe | I18N#Affix |
| 圣物名称/套装效果 | RelicBase.Name / *Des | I18N#Relic |
| 圣物等级效果 | RelicLevel.EffectDes | I18N#Relic |
| 时装外观 | AdornmentClothes.NameID | I18N#AdornmentClothes |
| 时装套装 | FashionSuit.NameID | I18N#Fashion |
| 道具 | Item.Name / Describe | I18N#Item |
| 富文本词条链接 | TermLink.NameID / DescriptionID | I18N#TermLink |

## 组织方式

已确认的 sheet 列表：

- I18N#Skill、I18N#Equip、I18N#Item、I18N#Enemy、I18N#Task、I18N#SystemFunction、I18N#Buff
- I18N#AdornmentClothes、I18N#Relic、I18N#Affix、I18N#Inscription、I18N#TermLink

字段格式：`Key` + `Lang#1.Name` / `Lang#1.Val` + `Lang#2.Name` / `Lang#2.Val` ...

## 富文本词条链接

- 词条链接表：`system/TermLink.xlsx#TermLink`
- 字段：`TermLinkID`、`NameID`、`DescriptionID`
- 引用方式：任意 I18N 富文本中写 `<link>TermLinkID</link>`，客户端点击下划线链接后按 `TermLinkID` 查词条 tips。
- `NameID` 和 `DescriptionID` 都是 I18N key，统一落在 `I18N#TermLink`。
- 示例：`TermLinkID=1`，`NameID=TermLink_Name_1`，`DescriptionID=TermLink_Describe_1`；I18N 富文本中写 `<link>1</link>`。
- `<link>` 内容必须是可转成数字的 `TermLinkID`；客户端会用 `TermLink.NameID` 对应文案替换链接显示文本。不要在 `<link>` 内再放双引号或嵌套其它富文本标签。

## 禁止事项

1. 不要给铭文变体技能配 I18N#Skill — 不会被读取
2. 不要给圣物/词缀被动技能配 I18N#Skill — 展示走各自业务 sheet
3. 不要把 I18N 当一张表 — 新增文案先确认落在哪个 sheet

## 维护原则

- 新增配置后及时补充 I18N Key
- Key 格式遵循 `约定/ID编码规范.md` 中的命名规则
- 先判断落在哪个业务 sheet，不能只说"补 I18N"
