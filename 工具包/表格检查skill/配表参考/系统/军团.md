# 军团配置

> 数据源：`develop/system/Guilds.xlsx`。最近验证：2026-09-21 / SVN r6595 / Excel 全量结构与 proto、服务端主要消费者只读核对。军团试炼看 `事实卡/Guild_Activity.md`，军团冲刺看 `commerce/UltimateGuilds.xlsx`，不要与本文件混表。

## 一、工作簿边界

`Guilds.xlsx` 同时承载军团基础、捐献与任务、分红、旗帜与功能入口、军团科技。各 Sheet 不是一套同构数据，先按下表定位：

| Sheet | 表角色 | 主键 / 分组键 | 主要引用 |
|---|---|---|---|
| `c.GuildConst` | 纵向常量 | 键名 | 创建/改名消耗、冷却、文本长度、旗帜、集结、科技重置、分红门槛 |
| `GuildLevel` | 等级主表 | `GuildLevel` | 人数、升级经验、每日经验上限、职位人数、开放功能、基础分红 |
| `GuildPermission` | 职位权限 | `GuildTitle` | I18N 职位名、权限枚举 |
| `GuildDonation` | 捐献档位 | `ID` | 消耗三元组、奖励三元组、次数、档位类型 |
| `GuildTask` | 军团日常任务 | `TaskItemConfig.TaskID` | 任务类型、目标、参数、奖励 |
| `GuildTaskStage` | 活跃度阶段奖励 | `StageID` | `NeedScore` 与奖励三元组 |
| `GuildFlag` | 旗帜素材 | `FlagID` | `Picture.PictureID` |
| `GuildDungeon` | 军团玩法入口 | `ID` | 排序、入口图、`SystemFunctionID` |
| `BonusExtraReward` | 周贡献额外奖池 | `ID` | 贡献闭区间与一组奖励 |
| `BonusExtraRank` | 分红排名权重 | 列表行 / `ID` | 排名闭区间与权重 |
| `GuildTechnologyStage` | 科技页签 | `StageID` | I18N 页签名、排序、开关 |
| `GuildTechnology` | 科技定义 | `TechnologyID` | 阶段、类型、I18N、Picture、前置科技 |
| `GuildTechnologyLevel` | 科技等级 | `TechnologyID + Level` | 升级消耗、属性效果 |
| `Sheet1` | 空白页 | 无 | 不参与配置，不作为新增数据落点 |

## 二、`c.GuildConst`

这是纵向 `@cfg:struct`，A/B/C 列分别是键、值、说明。不能按普通横表新增“字段列”。

### 基础与加入

| 键 | 语义 / 单位 | 关键边界 |
|---|---|---|
| `IsOpen` | 军团总开关，0/1 | 入口与服务端开放检查都要核 |
| `CreateCosts#N` | 创建消耗三元组 | 当前表为龙晶；改动反查创建接口 |
| `CreateVipLevel` | 创建所需最低 VIP | 0 表示不额外限制 |
| `CreateAgainCD` | 解散后再次创建冷却，秒 | 不要与离开后加入冷却混用 |
| `LeaveJoinCD` | 主动离开后加入新军团冷却，秒 | 主动离开 |
| `DissolveJoinAgainCD` | 被移出后重进原军团冷却，秒 | 原军团 |
| `DissolveJoinCD` | 被移出后加入其他军团冷却，秒 | 其他军团 |
| `JoinMaxTimes` | 每自然日最多加入次数 | 零点刷新 |
| `FilterMinLevel` | 搜索/筛选等级档，以 `-` 分隔 | 是分档串，不是单一等级 |
| `ApplyListCount` | 审批列表容量 | 与玩家当日申请次数不是一项 |
| `ApplyCDTimes` / `ApplyCD` | 连续申请达到次数后触发的冷却次数阈值 / 秒 | 必须成对核对 |
| `TodayApplyCount` | 玩家每日申请上限 | 自然日口径 |
| `ApplyExpireTime` | 申请未处理自动拒绝时长，秒 | `<=0` 时服务端回退为 7 天 |

### 管理、文本与生命周期

| 键 | 语义 / 单位 | 关键边界 |
|---|---|---|
| `RenameCosts#N` | 改名消耗三元组 | 当前 Excel 未列出时按空处理，不自行补默认价 |
| `RenameCD` | 改名冷却，秒 | 与任命冷却分开 |
| `GivenUpDays` | 会长未登录后转让判定，天 | 候选还受活跃与历史战力规则影响 |
| `ActivePlayerDays` | 活跃成员判定窗口，天 | 用于会长转让候选等逻辑 |
| `DissolveUnActiveDays` | 军团不活跃自动解散，天 | 不是成员离线天数 |
| `NewsListMaxCount` | 军团动态保留条数 | 配置缺失时服务端默认 50 |
| `AppointCD` | 任命会长冷却，秒 | 当前数值很小也按秒理解 |
| `DeclareMaxLength` | 宣言最大长度 | 与公告、名称、缩写分别控制 |
| `ShortNameMaxLength` | 缩写最大长度 | 不等于军团名长度 |
| `NoticeMaxLength` | 公告最大长度 | 玩家输入限制 |
| `NameMaxLength` | 军团名最大长度 | 玩家输入限制 |
| `DefaultFlag` | 默认旗帜组合，`;` 分隔 | 当前格式为“颜色 FlagID;图标 FlagID”，两项都必须命中 `GuildFlag` |

### 捐献、集结、科技、分红

| 键 | 语义 / 单位 | 关键边界 |
|---|---|---|
| `DonateRedDotThreshold` | 捐献红点材料阈值 | 是提示阈值，不是捐献价格 |
| `ConvenedCountdown` | 集结弹窗倒计时，秒 | 与集结冷却分开 |
| `ConvenedFreeTimes` | 每日免费集结次数 | 数量，不是时长 |
| `ConvenedProps` | 集结道具 ID | 命中 `Item.ItemID` |
| `GuildRallyCooldown` | 发起/接受成功后的集结冷却，秒 | 当前实现读取该常量 |
| `ResetTechnology#N` | 重置科技消耗三元组 | 由军团科技服务读取 |
| `DividendUnlockGuildLevel` | 分红解锁军团等级 | 未配置或 `<=0` 时当前服务端按 1 级 |
| `MiniPointsForBonus` | 个人获得分红的最低贡献 | 0 表示不额外卡个人贡献；不要与军团总贡献档位混用 |

## 三、等级、权限、捐献和任务

### `GuildLevel`

- `GuildLevel` 唯一且连续；`NeedExp` 是升级到下一等级所需经验，满级仍可获得经验但不再升级。
- `LimitCount` 是成员上限；`TodayLimitExp` 是当日可计入升级的军团经验上限。
- `Titles#N.Title/Value` 定义职位与该职位人数；职位必须命中 `GuildPermission.GuildTitle`。
- `SystemFunctionText` 是展示文本 key，落 `I18N#GuildLevel`；不是 `SystemFunctionID`。
- `BonusBaseReward` 是该军团等级下每个满足资格成员的基础分红。
- proto 还支持 `Privileges` 与 `UnlockTypes`；Excel 当前没有对应列时按空数组，不从旧需求补值。

### `GuildPermission`

- `GuildTitle` 是职位枚举主键；`PermissionTypes#N` 是该职位拥有的权限集合。
- `GUILD_PERMISSION_TYPE_ALL` 表示全部权限；当前服务端优先判这个枚举，再判具体权限。
- `GuildName` 是职位显示文案 key，关联 `I18N#GuildPermission`；普通成员当前为空时不能自造文案 key。

### `GuildDonation`

- `ID` 是捐献档位；`Donationtype` 是初级/高级/尊贵等档位类型。
- `Cost` 是支付成本，`Reward` 是返还的军团币、军团经验、金币等；三元组空槽必须整组为空。
- `CostLimit` 是该档位每日次数上限。
- proto 另有 `Contribution`，当前 Excel 没有该列；军团经验/贡献的当前口径必须结合服务端 `guildbasic` 读取，不凭奖励列表自行等同。

### `GuildTask` / `GuildTaskStage`

- `GuildTask` 复用通用任务组件：`TaskID` 唯一，`TaskType + TargetValue + TaskParams` 定义目标，`LanguageKey/LanguageParams` 定义任务描述，`Loot` 定义奖励。
- `GuildTaskStage.NeedScore` 是累计军团任务积分门槛，按 `StageID` 递增；`Rewards` 为阶段奖励。
- 新增任务类型前先确认任务引擎已支持对应 `TASK_TYPE` 与参数形态；不能只在 Excel 写中文枚举。

## 四、入口、旗帜与分红

### `GuildFlag` / `GuildDungeon`

- `GuildFlag.FlagType`：1 颜色、2 图标；`PictureID` 强引用 `system/Picture.xlsx#Picture.PictureID`。
- `DefaultFlag` 必须各取一个有效颜色和图标 ID；不要把 `PictureID` 直接写进常量。
- `GuildDungeon.SerialNumber` 控制展示顺序；`DungeonPicID` 引用 Picture；`SystemFunctionID` 引用功能解锁枚举。空 `SystemFunctionID` 表示未挂接功能。
- `GuildDungeon` 是军团玩法入口列表，不是副本关卡数据；军团试炼关卡仍在 `dungeon/GuildTrial.xlsx`。

### `BonusExtraReward` / `BonusExtraRank`

- `BonusExtraReward.Exp.MinData/MaxData` 是军团本周总贡献闭区间；区间必须连续、不重叠。`Rewards` 当前协议只允许一组道具。
- `BonusExtraRank.Rank.Min/Max` 是成员贡献排名闭区间；`RewardsProp` 是奖励权重。服务端按各档权重参与分配，不是直接奖励数量。
- 分红链还依赖 `GuildLevel.BonusBaseReward`、`GuildConst.MiniPointsForBonus` 和 `DividendUnlockGuildLevel`，不能单改一张分红表收口。

## 五、军团科技

1. `GuildTechnologyStage` 定义页签。`TabName` 关联 `I18N#GuildTechnology`，`Sort` 越小越靠前，`IsOpen=0` 时不展示。
2. `GuildTechnology` 定义科技：`StageID` 命中阶段；`TechnologyType` 当前 1 基础、2 高级；同阶段同类型内 `Sort` 唯一。
3. `TechnologyName/Desc` 关联 `I18N#GuildTechnology`；`Icon` 关联 `Picture.PictureID`，不是资源文件名。
4. `PreTechnologyID/Level` 是单项前置。基础科技首项可填 0；高级科技填 0 时由“全部基础科技满级”规则解锁，不能按“无条件解锁”理解。
5. `GuildTechnologyLevel` 用复合键 `TechnologyID + Level`；同一科技等级从 1 连续到 `GuildTechnology.MaxLevel`。
6. `Cost#N` 是升级到本级的单次消耗；一键升级会累计逐级成本。
7. `Effect.AttributeType/Value/ValueType` 是本级增量；`ValueType=1` 固定值，`2` 万分比。最终角色属性由已学各级增量汇总，不把某一行当累计总值。

## 六、配置顺序

1. 确认改的是基础军团、入口、任务、分红还是科技，不把 `GuildTrial`、`UltimateGuilds` 混进本表。
2. 先配被引用对象：Picture、Item/资源、I18N、SystemFunction、属性枚举。
3. 再配基础定义：等级/职位、旗帜/入口、科技阶段/科技定义。
4. 再配明细：捐献、任务/阶段、分红区间、科技等级。
5. 最后检查常量门槛和开关，避免定义齐全但入口关闭或门槛不可达。

## 七、最小验收

- 每个 Sheet 的主键或复合键无重复；连续等级无断档。
- 所有 `PropType/PropID/Value` 三元组完整，资源和道具按类型分流。
- I18N key、PictureID、SystemFunctionID、属性枚举全部命中。
- `GuildLevel.Titles` 能命中 `GuildPermission`；职位人数不超过成员上限。
- 分红贡献区间与排名区间不重叠、不倒置，权重非负。
- `GuildTechnology.MaxLevel` 与等级表实际最大等级一致；前置科技存在且不会形成环。
- 所有秒/天/万分比字段按单位检查，不能用显示文本猜单位。
- 空 `Sheet1` 保持空白，不作为临时落点。
