### Adventure 主线链路

首轮入口：`事实卡/Adventure.md`。本文只保留长链解释和历史回填经验。

冒险不是只看 `AdventureBarrier`。当前稳定读法：

```text
AdventureChapter.AdventureAreaID
  -> AdventureArea.AdventureBarrierID
  -> AdventureBarrier.Fixed_AdventureWeakEnemyRoomID / Random_AdventureWeakEnemyRoomID / AdventureStrongEnemyRoomID
  -> 弱怪房 / 强怪房
	-> SceneID
	-> EnemyID 列表 / BossData / 掉落等级
  -> Enemy / EnemyAttrGrow / MonsterAI / Skill
```

配置习惯：

- `AdventureChapter` 负责章节和地图表现；`AdventureArea` 负责区域到关卡集合，同时承载解锁条件、领取奖励、倒计时、广告 / 道具加速和进入下一区域 / 章节的状态机；`AdventureBarrier` 负责单关节点、房间、掉落等级和地图点位。
- 章节、区域、关卡、房间之间大量使用分号分隔列表，不是标准单外键。
- 弱怪房和强怪房 ID 有段位习惯，例如弱怪房、随机弱怪房、首领房分段命名；改房间前先按 ID 家族反查，不要只搜一个字段。
- 冒险“通关关卡”进度以是否击杀 Boss 为界：未击杀 Boss 时进度按上一关计算，击杀后才算当前关卡通关。
- 小怪房运行时会先选 `EnemyNumPlans` 数量方案，再逐波从 `Waves#N.EnemyID` 和 `Waves#N.PosID` 池抽取；Boss 房直接按 `BossData / HelperData` 创建。
- 怪物等级和属性不是房间表决定：`Enemy.Level.Type` 决定等级来源，最终必须命中 `EnemyAttrGrow`；AI 和技能继续从 `Enemy.EnemyAI`、MonsterRes、Skill 链路解释。

### Adventure 数值表回填口径

当从养成数值表回填冒险和怪物成长时，数值表是事实源，源表现有旧样例只能作为格式参考，不能反推覆盖数值表。

- 当前版本范围必须从链路判断：`AdventureChapter.AdventureAreaID` 挂到哪些区域，`AdventureArea.AdventureBarrierID` 再挂到哪些关卡。只配置到某个版本范围时，范围外但未被挂接的历史 / 预留行不要自行删除。
- `AdventureArea.MaxLevelData` 取数值表 `冒险` 的“突破后限制等级”；没有突破后值时取“突破前限制等级”。`GatherMinute` 取“区域解锁所需时间（秒） / 60”。
- `AdventureArea.EquipQualityRandomID` 和 `EquipPartRandomID` 按区域 ID 挂同编号随机组；不要只改 Area，不回查 `random/Random.xlsx`。
- `EquipQualityRandom` 以数值表 `冒险` 的“品质掉落-1~6”类型 / 概率为准，`Weight = 概率 * 10000`。备注不是功能事实源；如果维护备注，备注里的品质名必须跟 `TargetType` 一致，不能保留复制残留。
- `EquipPartRandom` 以数值表 `冒险` 的 `装备部位 / 部位名称 / 掉落权重` 模板为准。该块是冒险装备部位随机的统一模板；回填当前冒险区域时，各区域随机组都按这个模板落，不要沿用旧表中局部区域的 `600/1200/...` 样例。
- `AdventureDropLevel.ExpDropsData` 取数值表 `冒险` 的“关卡经验产出”，并保持 `AdventureBarrier.AdventureDropLevelID` 与关卡一一对应。
- 冒险引用完整性至少检查：`AdventureArea -> AdventureBarrier -> AdventureWeakEnemyRoom / AdventureStrongEnemyRoom -> SceneID / EnemyID / BossData / AdventureDropLevelID`，并补查 `scene/Scene.xlsx`、`battle/Enemy.xlsx`、`battle/MonsterAI.xlsx`、`system/Animation.xlsx`、`random/Random.xlsx`。

`battle/EnemyAttrGrow.xlsx#EnemyAttrGrow` 的冒险相关成长按数值表 `怪物属性` 全模板录入，不只录当前被关卡引用到的怪。

- 数值表 `怪物属性` 横向模板按 4 个稀有度（喽啰 / 精英 / 统领 / 首领）× 3 个强度组织，每个模板内含 3 个职业 × 120 级。
- `EnemyAttrGrow.AttrGrowId` 使用“玩法两位 + 职业 + 稀有 + 强度 + 3 位等级”的编码。冒险小怪房用玩法前缀 `10`，冒险首领房用 `11`，金猪牧场用 `12`。
- 10 / 11 / 12 三类都要按 `怪物属性` 模板完整生成：每类 3 职业 × 4 稀有 × 3 强度 × 120 级 = 4320 行。
- 源数值表出现小数时，落表为整数；最终 `EnemyAttrGrow` 不保留公式和小数。
- `Enemy.xlsx` 中跟随冒险关卡等级的动态怪，即使 `Level.MinData / Level.MaxData` 为空，也要能落到对应玩法前缀下 1~120 级成长模板，不能因为当前表里没有固定等级就漏配。

### WorldHunting 链路

首轮入口：`事实卡/WorldHunting.md`。世界狩猎复用冒险式房间结构，但当前 Excel 的 Boss 入口、刷新和奖励链独立；旧章节 / 任务结构仅用于迁移核对。

Excel 当前配表结构为：

```text
BossHunting.ID
  -> BossRoomID -> HuntingBossRoom -> SceneID + BossData
  -> Reward#N -> Item / Chest
  -> SoulStoneChestID#1..#7 -> WorldHuntingDropRule
  -> 数量 / 套装 / 星级 / 部位四类权重 -> SoulStone
```

配置习惯：

- `BossRoomID` 是房间引用，不是场景 ID；房间行里再填 `SceneID` 和 `BossData`。
- `SoulStoneChestID#1..#7` 是周一至周日 DropRule 外键，不是 Item/Chest ID。
- `SoulStoneRandomCount` 次抽取独立执行，数量权重允许 0；不能写成至少掉落 N 个。
- `RespawnTimeMin/Max` 控制每个 Boss 房独立随机刷新，和 `HoldLootTime/AutoLeaveTime` 分开。
- 掉落权重不再按职业分列。`WorldHuntingDropRule` 与 `SoulStoneDungeonDropRule` 现在都是 `StoneNumWeights` / `SetWeights` / `StarWeights` / `PositionWeights` 四列，**两个职业的套装要配在同一个 `SetWeights` 里**，运行时由服务端按玩家职业过滤（`FilterSetWeightsByProfession`）；数量、星级、部位三类与职业无关。四类权重任一为空或非法都会报配置错误。
- 旧的 `ChapterID` / `EnemyRoomID` / `TaskID` / `DropPoolID` 已从 `BossHunting` 移除，服务端狩猎结算改走 `GetSoulStoneDungeonDropRuleWeightsByID`，与魂石副本共用同一套取数与抽取逻辑。上一轮"程序待接入、不能直接发布"的提示不再适用。

### SoulStoneDungeon 链路

```text
SoulStoneDungeonBoss
  -> RoomID -> SoulStoneDungeonRoom -> Scene / Enemy
  -> SoulStoneDropRuleID#1..#7 -> SoulStoneDungeonDropRule
  -> Condition / SoulStone / Item / Chest
```

四个 sheet 的字段口径见 `事实卡/SoulStoneDungeon.md`；`SoulStoneDungeonDropRule` 与 `WorldHuntingDropRule` 共用同一套权重结构和服务端抽取逻辑，但**仍是各自独立的主键空间，不得合表**。

抽取顺序：先按 `StoneNumWeights` 定本次出几颗，再对每颗独立抽 `SetWeights` / `StarWeights` / `PositionWeights`，用（套装, 星级, 部位）反查魂石 ID；查不到组合会报错，因此三类权重里出现的取值必须在魂石表里有对应实体。

`SoulStoneDungeonBoss` 本轮新增 `Name`（层数名称），奖励位扩到 3 组。

### 入口、解锁和跳转链路

副本入口通常分三层：

```text
Dungeon.SystemFunctionID
  -> system/SystemFunction.xlsx#SystemFunction.UnlockCondID / PromptID / SerialNumber
  -> system/Window.xlsx 或 system/Jump.xlsx
  -> system/Condition.xlsx / system/Prompt.xlsx / system/I18N.xlsx
```

配置习惯：

- `Dungeon` 更像副本目录页，不是具体战斗波次表。
- `Dungeon.WindowID` 是副本列表点击后打开的窗口；`Dungeon.SystemFunctionID` 主要用于锁定态、红点和功能开放语义。`Window` 管界面展示，`Jump` 管按钮或跳转方式，三者不要混用。
- 解锁条件经常是 `GC_*` 这类命名键，先按条件表解释，不要当成普通字符串。

### Task 链路

- `task/Task.xlsx#MainTask` 通过 `TaskItemConfig.NextTaskID` 串主线任务链。
- 任务目标由 `TaskItemConfig.Targets#N.TaskType / TargetValue / TaskParams` 组成，奖励由 `Loot#N.*` 承接。
- 世界狩猎等玩法会在自己的表里引用任务模板；看到 `TaskID` 列表时要反查任务表或该玩法专属任务 sheet。

### PiggyDungeon（金猪牧场 / 金币副本）

`PiggyDungeon` 是金币副本 / 金猪牧场配置。当前程序语义已确认包含：扫荡、广告扫荡、免费次数、钻石消耗、每日重置、免费扫荡红点，以及通关后推进到下一个 `PiggyID`。业务定位、奖励落点和入口挂接仍需确认。

首轮链路见 `事实卡/Dungeon_System.md`。核心配置闭合方式：

```text
Dungeon / SystemFunction
  -> PiggyDungeon.ID
  -> SceneID + EnemyData / BossData
  -> Enemy / EnemyAttrGrow / MonsterAI / Skill
  -> BarrierReward / SweepReward / SweepRandom
  -> Item / Resource / Random
```

服务端会把 `EnemyData`、`BossData` 解析成出生点数据；扫荡消耗和广告免费次数来自 `ConstComm`。配新关时不要只补 `PiggyDungeon` 行，必须同步查怪物、场景、奖励、常量和入口。

### BloodSearch（寻血仪式）

首轮链路见 `事实卡/Dungeon_System.md`。寻血不是单战斗关卡表，而是事件、奖励、每日奖励、地图点位和常量共同组成：

```text
ConstComm BloodSearch_*
  -> BloodSearchMapPoints
  -> BloodSearchEvent.SceneID + NpcData + RewardID
  -> BloodSearchReward / BloodSearchDaily
  -> WinReward / FailReward / Reward
```

`BloodSearchEvent.NpcData` 解析为 NPC 出生点和 EnemyID；`RewardID` 指向 `BloodSearchReward`；奖励出现 / 消失条件按该玩法语义解释，不能只按普通 Condition 字段处理。

### Arena（王城竞技场）

首轮链路见 `事实卡/Dungeon_System.md`。竞技场配置分成全局、段位、排名奖励、积分差和战令：

```text
Arena
  -> ArenaTier
  -> ArenaReward
  -> ArenaScoreDiff
  -> ArenaBattlePass
  -> Rank / Mail / Loot / PurchaseList
```

服务端按 `Arena.OpenTime` / `GroupTime` 判断开放时间，按 `ArenaScoreDiff` 区间算胜负积分。改赛制、排名奖励、战令、付费或跨服匹配时都属于高影响配置，必须额外确认玩法规则。
