## 跨表引用（已确认链路 + 需确认边界）

### ActivitySchedule 驱动 → reward/ 各表展示

活动排期决定"什么时候展示哪个礼包/活动"。当前已确认 `ActivityInfo` / `ActivitySchedule` 与多张 `reward/` 表通过 `ActConfigID` 或 `ActivityID` 承接；未列出的活动类型仍需现场确认：

- 黑金商会活动 → `reward/BlackGold.xlsx`（飞书策划原文：《【FF】黑金商会（集换）》）
- 嘉年华 → `reward/Carnival.xlsx`
- 多档礼包 → `reward/MultiStageGiftPack.xlsx`
- 新服特权 → `reward/NewServerPrivilege.xlsx` / `reward/NewServerRank.xlsx`
- 首充 / 新手礼 → `reward/StarterPack.xlsx` / `reward/PromoPack.xlsx`
- 限时礼包 → `reward/LimitPackage.xlsx`
- 目标冲刺 → `reward/TargetRush.xlsx`
- 通用基金 → `reward/UniversalFund.xlsx`
- 特权卡 → `reward/PrivilegeCard.xlsx`
- 签到 → `reward/Sign0.xlsx`
- 日常任务 → `reward/DailyTask.xlsx`

`ActConfigID` 是活动配置 ID，编码规则为“活动类型枚举值 * 1000 + 扩展序号”。`ActivityInfo.ActConfigID` 与 `ActivitySchedule.ActConfigID` 必须一一对应，下游业务表中同语义字段同步使用这套长 ID。

已确认直接承接字段：

- 首充 / 新手礼 → `reward/StarterPack.xlsx#StarterPackGroup .ActCfgID`
- 符文 / 宠物 / 生产 / 挂机冲刺 → `reward/TargetRush.xlsx#TargetRushInfo.ActCfgID`、`TargetRushTask.ActCfgID`、`TargetRushPack.ActCfgID`、`TargetRushStore.ActCfgID`
- 竞技场战令 → `dungeon/Arena.xlsx#ArenaBattlePass.Pid`
- 触发礼包 → `reward/LimitPackage.xlsx#LimitPackage.ActCfgID`
- 每日 / 每周 / 每日特惠 → `reward/PromoPack.xlsx#PromoPackDaily.ActivityID`、`PromoPackWeekly.ActivityID`、`DailyPromo.ActivityID`、`DailyPromoExtraReward.ActivityID`
- 一元特惠 → `reward/SpecialOffer.xlsx#SpecialOffer.ActivityID`
- 多段礼包 → `reward/MultiStageGiftPack.xlsx#MultiStageGiftPack.ActivityID`、`MultiStageGiftPackRes.ActivityID`、`MultiStageGiftPackStage.ActivityID`
- 新手专题榜单 → `reward/NewServerRank.xlsx#NewServerRankReward.ActivityID`、`NewServerRankTask.ActCfgID`
- 基金 → `reward/UniversalFund.xlsx#UniversalFund.ActivityID`、`UniversalFundPurchase.ActivityID`

不要把 `PackID`、`GroupID`、`BindID`、奖励值、资源 ID 等撞号字段误当活动配置 ID；这些字段有自己的派生或分组规则。

配置习惯：

- `ActivitySchedule` 是开放窗口，`ActivityInfo` 是活动入口 / 展示信息，下游奖励表是具体内容。不要把三层压成一张“活动表”理解。
- `ActivityInfo.ThemeResID` 选择客户端活动主题资源目录，不是 `PictureID`；改主题时需验证对应 `Prefabs/{id}` 与纹理目录。
- `commerce/MultiTaskAct.xlsx` 已于 SVN r6458 删除；当前正式多任务活动表是 `reward/MultiTaskAct.xlsx`，旧路径不再参与定位与联查。
- `UltimateGuildsIntegral/UltimateGuildsText` 已有客户端展示消费；服务端积分累计、排名结算和发奖链仍需确认，不能从页面可见反推玩法已完整接入。
- 服务端 `ActivitySchedule.ConditionID` 走公共 Condition；空条件视为通过，非空条件必须能在 `system/Condition.xlsx` 命中并被代码解释。
- `ActivitySchedule` 的运行时间窗按四段理解：`PreheatTime` 是开始前预热秒数，`StartTime` 到 `EndTime` 是活动期，`ShowTime` 是结束后继续展示秒数；服务端会把结束点按“结束前 1 秒”处理，配置边界时间时不要把 `EndTime` 当成仍可参与的最后整秒。
- 同一个活动内容可以有多条排期。抽样中 `ActConfigID=2001001`、`3001001`、`5001001` 都能看到多条 schedule 行。
- 同一个 `ActType` 在当前通用活动流程中默认同轮只会上一个活动；需要同类型多活动并存时，必须确认该活动是否接入多活动注册通道，不能只靠多配几条排期解决。
- `ActConfigID` / `ActivityID` 是活动层配置键；`PackID` 是礼包内部档位；`PurchaseID` 是支付项；`GroupID` / `BindID` / `MutexGroupID` 是礼包组织或互斥关系。字段撞号时按所在表语义解释。

### AutoPopup 对接

`AutoPopup` 管弹窗出现时机和次数限制：

- `Type`：自动弹框业务类型。
- `PopupType`：弹框时机，如登录。
- `GroupID`：弹框组，关联 `AutoPopupGroup.GroupID`。
- `Index`：组内顺序。
- `DailyCount` / `TotalCount`：每日和总次数限制。
- `DurationSec`：持续秒数。
- `TriggerEvent` / `Params#N`：触发事件及参数。

`AutoPopupGroup` 管组级限制和优先级：

- `GroupID`
- `LimitNum`
- `Priority`

自动弹窗常见联查：

- 活动内容：`ActivitySchedule` / 对应 `reward/*.xlsx`
- 触发事件：`system/SystemEvent.xlsx`
- 弹窗文案：`system/Prompt.xlsx` 或业务 I18N sheet
- 入口跳转：`SystemFunction` / `Jump` / `Guide`
- 解锁或购买条件：`Condition`

隐藏关系：

- `AutoPopup` 不一定直接填活动 ID；常见触发轴是 `PopupType + TriggerEvent + Params#1`。
- `AutoPopup.Params` 按“配置参数全部被事件参数包含”判断命中，顺序不重要，事件可以带更多参数；不要只看 `Params#1`。
- `GroupID` 在 `AutoPopup` 里是弹窗组，和礼包表里的 `GroupID` 不是同一个业务概念。
- 如果活动需要登录弹窗、触发弹窗或限次弹窗，要从活动内容反查 `AutoPopup`，不能只看 `ActivitySchedule`。
- 登录自动弹窗不是进游戏瞬间立刻弹：客户端会等主玩法进入完成和活动初始化完成两个信号。
- 同批弹窗按 `AUTO_POPUP_TYPE + GroupID + Index` 去重；每日 / 总次数也按该行级身份计数。

### Subcribe 对接

`system/Subcribe.xlsx` 是订阅推送配置，源表文件名当前拼作 `Subcribe`，引用时按源表原名。

- `SubscribePush`：场景、固定推送时间、间隔推送时间。
- `SubscribeFailTipInterval`：订阅失败次数和下次提示间隔。
- `备注`：字段说明。

订阅推送和自动弹窗类似，不能只看时间字段；需要同步判断触发场景、提示文案和入口是否存在。

### PurchaseList 对接

- `system/Store.xlsx` / `system/Item.xlsx`（商品实际落地）
- `system/I18N.xlsx`（价格、档位文案）

付费链路按三层读：

1. `commerce/PurchaseList.xlsx#PurchaseList`：支付项，核心是 `PurchaseID` 和价格。
2. `system/Store.xlsx`：展示 / 售卖入口，例如 `RechargeStore`、`PackStore`。
3. `reward/*.xlsx`：礼包、活动或奖励内容，通常再引用 `PurchaseID` 或活动配置键。

`PurchaseID` 不等于 `PackID`。配付费礼包时先确认支付项是否存在，再看商店入口，最后检查奖励内容。

### NewServerPrivilege 对接

代码确认的新服特权展示链：

```text
ActivitySchedule / ActivityInfo
  -> reward/NewServerPrivilege.xlsx#NewServerRound.RoundID
  -> NewServerRound.PurchaseID
  -> PurchaseList
  -> NewServerPrivilege.ID / Round / Consumption / AdventureExp / AdventureDrop / EquipReCoin
```

客户端未购买时按当前有效 `Round` 找 `NewServerRound.PurchaseID`；等级配置按轮次和等级读取，当前展示上限为 7 级。自动弹窗还会检查 `FEATURE_UNLOCK_TYPE_NEW_SERVER_PRIVILEGE` 是否已解锁。新服排行 `NewServerRank` 的结算发奖触发仍需按服务端/策划继续确认。

Store 分流：

- `PackStore.PurchaseID` 为空时走道具兑换链路；非空时走支付链路。
- `RechargeStore` 首购奖励会按首购规则放大，`RechargeStoreBonus` 还要按轮次、合服次数和全领奖状态判断，不是独立商品本体。
