## 奖励承接模板

先判断奖励发放的是哪一类：

| 奖励形态 | 优先联查 | 检查点 |
|---|---|---|
| 直接发资源 / 道具 | `system/Item.xlsx#Item` / `system/Resource.xlsx#Resource` | `PropType`、`PropID`、数量、背包页签、堆叠和溢出 |
| 固定箱 | `system/Item.xlsx#GuaranteedChest` | `ChestID`、固定 `Reward#N.*` |
| 随机箱 | `system/Item.xlsx#RandomChest` | `AlgorithmType`、权重、数量上下限 |
| 自选箱 | `system/Item.xlsx#SelectionChest` | `SelectNum`、可选奖励列表 |

本轮三种箱子（`GuaranteedChest` / `RandomChest` / `SelectionChest`）都新增了 `ProfessionType`：同一个箱子 ID 下按职业区分发放内容，配的时候三张表要一起核对，漏配职业行会导致该职业开箱拿不到东西。`system/Item.xlsx#Item` 另新增 `BoxQuality`（品质特效），控制开箱表现档位，与掉落内容无关。
| 装备箱 | `system/Item.xlsx#EquipChest` | 装备等级、权重、装备奖励类型 |
| 活动配置奖励 | 对应 `reward/*.xlsx` + `commerce/ActivitySchedule.xlsx` | `ActivityID` / `ActCfgID` 与活动排期一致 |
| 付费礼包 | `commerce/PurchaseList.xlsx` + `system/Store.xlsx` + 对应 reward 表 | `PurchaseID`、价格、商品内容、限购和入口 |

不要把 `ActivityID` / `ActCfgID` 与 `GroupID` / `PackID` / `BindID` 混用。前者是活动配置或排期链路，后者通常是礼包内部组织、互斥或分组。

付费类奖励还要区分“购买”和“领取”：

- `UniversalFund` 购买只标记付费状态；免费奖励和付费奖励都通过基金领取入口发放，不是购买后立即发全量奖励。
- `PackStore.PurchaseID` 为空时是道具兑换；非空时是支付购买。
- `RechargeStore` 首购可能放大奖励，`RechargeStoreBonus` 是充值额外奖励轮次，不是单独商品本体。

## 多行活动配置习惯

奖励表经常不是“一行一个活动”，而是同一个活动键下多行组成内容：

- `StarterPack.xlsx#StarterPackGroup `：同一个 `ActCfgID` 下按 `PackID` 拆多个礼包档位，付费档通过 `PurchaseID` 接支付项。
- `StarterPack.xlsx#StarterPackInfo`：同一个 `PackID` 下按 `Day` 拆每日奖励；客户端从服务端返回的 `StarterPackInfo.PurchaseID` 做购买映射。
- `TargetRush.xlsx#TargetRushPack`：同一个 `ActCfgID` 下按 `PackID` 组织免费 / 付费礼包，内容还会和 `TargetRushInfo`、`TargetRushTask`、`TargetRushStore` 共用活动键。
- `LimitPackage.xlsx#LimitPackage`：同一个 `ActCfgID` 下还要看 `GroupID`、`BindID`、`MutexGroupID`、`StageID`、触发次数和限购字段；它不是简单礼包列表。
- `MultiStageGiftPack.xlsx`：按 `ActivityID + StageID` 组织阶段内容，资源表现、阶段和礼包内容分 sheet 维护；`MultiStageGiftPack` 是礼包内容行，`MultiStageGiftPackStage` 是阶段奖励行。

读活动奖励时，先按活动键聚合，再按礼包档位、阶段、互斥组拆开；不要只抽一行判断整个活动。

## 箱子承接习惯

- 奖励表里的 `Loots#N.*`、`Reward#N.*`、`Item#N.*` 最终通常落到 `system/Item.xlsx` 或资源表。
- 如果奖励发的是箱子道具，继续查 `Item.xlsx` 的 `GuaranteedChest` / `RandomChest` / `SelectionChest` / `EquipChest`。
- 抽样中活动奖励会引用箱子 ID 段，例如随机箱、自选箱再二次承接具体奖励。看到箱子 ID 时不能停在 `Item` 主 sheet。
- 随机奖励要继续查 `random/Random.xlsx` 或箱子内部权重字段；同一个池 ID 多行才是完整池。

### 竞技场红品铭文承接

- `dungeon/Arena.xlsx#ArenaReward` 的红品铭文按最高品质铭文承接；当前源表中红品对应 `system/Item.xlsx#RandomChest` 的 `3000009`（随机铭文宝箱神话），其内部奖励是 36 个最高品质铭文 ID。
- 指定红品铭文使用 `system/Item.xlsx#SelectionChest` 的 `3000010`（自选铭文宝箱-神话），`SelectNum=1`，`Reward#1` 至 `Reward#36` 对齐 `3000009` 的 36 个铭文 ID。
- `SelectionChest` 是 `@cfg:map|ChestID`，同一个 `ChestID` 不能拆多行表达同一个自选池；需要更多可选项时扩展同一行的 `Reward#N.*` 列。
- 新增箱子道具必须同步 `system/Item.xlsx#Item`、`system/Item.xlsx#SelectionChest` 和 `system/I18N.xlsx#I18N#Item`，避免奖励可发但背包展示缺文案。
