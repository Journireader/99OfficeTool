# 战斗配表实施入口

本文件只保留战斗实施层入口，避免和 `战斗_ECE管线.md` 重复维护 ECE 细节。配被动、Buff、词缀、圣物、铭文前，先读 `战斗_ECE管线.md`。

## 核心原则

**Skill 表里的一行不等于玩家看到的一个“技能”。** 多个 SkillID 组合在一起，才构成一个完整业务效果。Skill 表每一行只是最小执行单元。

Skill 是战斗逻辑中心枢纽，但展示文案各走各的：

- 基础版技能：`Skill.Name / Describe / Keyword` -> `I18N#Skill`
- 铭文：`Inscription.Name / Describe` -> `I18N#Inscription`
- 词缀：`Affix.Name / Describe` -> `I18N#Affix`
- 圣物：`RelicBase.Name / *Des`、`RelicLevel.EffectDes` -> `I18N#Relic`

## 表串联关系

```text
Inscription.PrimaryProfession#N.SkillID -> Skill
Inscription.PrimaryProfession#N.Name / Describe -> I18N#Inscription

Affix.SkillIDs -> Skill
Affix.Name / Describe -> I18N#Affix

RelicBase.IcePool / FirePool -> RelicPool
RelicBase.Three* / Two*ID -> Skill
RelicBase.Name / *Des -> I18N#Relic

RelicLevel.Effect -> Skill
RelicLevel.EffectDes -> I18N#Relic

Skill.SkillDirectorID -> SkillDirector
Skill.CastEventID -> BattleEvent
Skill.Effects#N.ConditionID -> BattleCondition
Skill.Effects#N.TypeID / TypeData -> Effect 字典
```

## ECE 入口

ECE 细节统一维护在 `战斗_ECE管线.md`，包括：

- Event / Condition / Effect 管线。
- Skill 和 Buff 两种载体。
- BuffEffectType（简称 BuffType）叠加规则。
- 常用组装模式。
- 字典常见误读。
- 配表前检查清单。

不要在本文重复写 ECE 规则；新增或修正 ECE 经验时，优先改 `战斗_ECE管线.md`。

## I18N 入口

战斗相关 I18N 路由统一看：

- `系统/I18N.md`
- `系统/战斗_I18N映射.md`
- `约定/ID编码规范.md`

禁止事项：

1. 不要给铭文变体技能配 `I18N#Skill`。
2. 不要给圣物 / 词缀被动技能配 `I18N#Skill`。
3. 不要把 I18N 当一张表；新增文案先确认落在哪个业务 sheet。
4. 不要不看编码规则猜 SkillID 含义；必须按 11 位拆解。
5. 不要让被动 Skill 缺 `CastEventID`；被动必须配置时间点，内部 helper 被动也一样。细则见 `战斗_ECE管线.md §1.1.1`。
