# 战斗 I18N 映射

> 用途：5 个战斗系统（Skill / Affix / Relic / Inscription / Buff）的 I18N Key 路由统一表 + 检测方法。
> 术语：本文统一用 `配表参考/约定/战斗术语对照表.md` 选定的术语。
> 数据源：`配表参考/系统/I18N.md`、`配表参考/约定/ID编码规范.md`、`配表参考/系统/词缀圣物.md`、`配表参考/系统/骑士技能.md`。

---

## 1. 核心原则

`I18N.xlsx` 不是一张表，是按业务拆成的几十个 sheet。每个业务的展示文案由各自 I18N sheet 管理，**禁止共用 I18N#Skill**。

- **基础版技能**（C=0 D=0）→ 玩家直接看技能名/描述 → 配 I18N#Skill
- **铭文变体技能 / 圣物被动 / 词缀被动** → 玩家看的是各自业务描述 → 各自的 I18N sheet
- **Buff** → Buff.Name / Describe 统一落 `I18N#Buff`；战斗中是否直接展示 Buff 名由具体 UI 决定，但 key 归属不走 I18N#Skill

### 1.1 战斗玩家文案口径

战斗玩家可见描述按当前配置机制写，但不暴露配置数值和内部实现细节：

- 不写伤害系数、倍率、百分比概率、CD、内部阈值；技能分类文案使用“核心类”，不写“怒气类 / 怒气技能”这类历史设计称呼。
- 词缀、圣物、铭文等正文不写伤害系数、概率数值、层数上限、次数上限等配置值；持续时间、触发间隔、效果结束时机可以写，但要按玩家 tooltip 口吻表达，例如 `持续 10 秒`、`每 2 秒`、`效果结束时`。
- 例外：`RelicLevel.EffectDes` 是圣物每级升级收益展示，按每级实际 Skill / Buff 配置写当前等级数值（百分比、固定概率、持续 / 冷却、层数 / 次数等玩家可比较的展示值），但不写 EffectID、TypeData、公式字段名等内部实现细节。
- Buff 描述必须加粗；写清持续时间 / 间隔、是否叠加、重复获得 / 重复施加时如何处理、是否刷新持续时间，但**不写伤害系数、伤害百分比或攻击倍率**。同一 key 被多个不同持续时间的 Buff 复用时，不硬写具体秒数，改用 `持续期间`、`定期`、`效果结束时` 等通用表达。
- 合并待结算量时，伤害类写 `剩余伤害并入新伤害`；治疗类写 `剩余治疗量并入新治疗`；是否刷新持续时间必须按 Buff 叠加规则另写，例如 `并刷新持续时间` 或 `但不会刷新持续时间`。不要写 `剩余效果并入新效果`。若实际机制是覆盖旧效果，不写合并，写 `以新效果为准并刷新持续时间`。
- Skill.Keyword 只写两个字纯文本标签，不加 `<link>`，不写技能名；例如 `核心`、`职业`、`爆发`、`普攻`、`技能`。
- TermLink 描述按对应 Buff 口吻直述，不写 `生效方式随触发它的技能或效果变化` 这类泛描述；能确定主概念时直接写 `目标进入流血状态...`、`获得护盾...`。TermLink 表达具体 Buff 变体时，名称也跟随 Buff 命名，例如全境守护系写 `全境守护`、`全境守护-复仇天使`，不要另造 `守护增幅` 这类泛名。
- 所有玩家描述的 `<link>` 都只给少量关键状态 / Buff / 异常（如 `流血`、`内出血`、`眩晕`、`护盾`），同一术语只在首次出现处加，单条描述不做密集 link。属性、伤害类型、冷却、概率、技能分类、技能名等直接写纯文本；TermLink 描述不链接自己。铭文描述额外要求不写具体技能名。
- 检查、监听、计数、空效果、隐藏且无展示路径的 Buff 不补玩家描述；如果客户端必须展示，先确认展示路径和玩家概念，再补 I18N。
- 同一个 Buff Name / Describe key 不要混用多个玩家概念。机制不同但历史共用 key 时，优先拆 key；例如护盾和属性强化不能共用同一个“护盾”词条。
- 铭文、圣物、词缀的被动 Skill 不写 `I18N#Skill` 展示描述；玩家正文落各自 I18N sheet。基础版技能可写自身 `Skill.Describe / Keyword`。

## 2. 5 系统 I18N 路由表

| 系统 | 配表字段 → I18N Sheet | Key 命名规则 | 示例 |
|---|---|---|---|
| **Skill（基础版）** | `Skill.Name` → `I18N#Skill`<br>`Skill.Describe` → `I18N#Skill`<br>`Skill.Keyword` → `I18N#Skill` | `Skill_Name_{SkillID}`<br>`Skill_Describe_{SkillID}`<br>`Skill_Keyword_{SkillID}` | `Skill_Name_2111010001`<br>（骑士基础-武器线第1段普攻） |
| **Skill（铭文变体）** | **不配 I18N#Skill**<br>玩家看 I18N#Inscription | — | — |
| **Skill（圣物/词缀被动）** | **不配 I18N#Skill**<br>玩家看 I18N#Relic / I18N#Affix | — | — |
| **Affix（词缀）** | `Affix.Name` → `I18N#Affix`<br>`Affix.Describe` → `I18N#Affix` | `Affix_Name_{AffixID}`<br>`Affix_Describe_{AffixID}` | `Affix_Name_6` |
| **Relic（圣物本体）** | `RelicBase.Name` → `I18N#Relic`<br>`RelicBase.RelicDes` → `I18N#Relic`<br>`RelicBase.IceDes / FireDes / Ice3Des / Fire3Des / Ice2Des / Fire2Des` → `I18N#Relic` | `Relic_Name_{RelicID}`（7 位）<br>`Relic_RelicDes_{RelicID}`<br>`Relic_IceDes_{RelicID}` 等 | `Relic_Name_4000101`<br>`Relic_IceDes_4000101` |
| **Relic（等级效果）** | `RelicLevel.EffectDes` → `I18N#Relic` | `Relic_LevelDes_{SkillID}`（11 位） | `Relic_LevelDes_31001010101` |
| **Inscription（铭文）** | `Inscription.Name` → `I18N#Inscription`<br>`Inscription.Describe` → `I18N#Inscription` | `Inscription_Name_{N}`<br>`Inscription_Des1_{N}` 等（4 阶逐阶累加） | `Inscription_Name_1`<br>`Inscription_Des1_1` |
| **Buff** | `Buff.Name` / `Buff.Describe` → `I18N#Buff` | 沿 `Buff` 表已填 key；常见为 `Buff_Name_*` / `Buff_Describe_*` 等 | `Buff_Describe_10` |

## 3. 配表字段 → I18N Key 详细路由

### 3.1 Skill 基础版（C=0 D=0）

判据：`SkillID` 第 6 位（C） = 0 且 第 7 位（D） = 0。

```
Skill.Name      → I18N#Skill.Skill_Name_{SkillID}
Skill.Describe  → I18N#Skill.Skill_Describe_{SkillID}
Skill.Keyword   → I18N#Skill.Skill_Keyword_{SkillID}（关键词标签，如"必杀"/"领域"）
```

例：骑士基础线第 1 段普攻
- SkillID = `2111010001` → 21（骑士） + 1（基础线） + 1（武器系） + 0（变体=基础） + 0（阶=基础） + 00001
- Name Key = `Skill_Name_2111010001`

### 3.2 Skill 铭文变体（C≠0 或 D≠0）

**不配 I18N#Skill**——铭文变体的展示文案由 Inscription 表统一管理。

例：骑士武器系铭文 1 阶第 1 段普攻
- SkillID = `2111110101`（C=1 D=1）→ I18N 走 Inscription 路由

### 3.3 Skill 圣物被动（前缀 31）

**不配 I18N#Skill**——展示走 RelicLevel.EffectDes 或 RelicBase.*Des。

例：誓印 01 等级 1 效果（誓印旧名"护符"）
- SkillID = `31001010101`（11 位）
- 在 RelicLevel 中：EffectDes 字段 = `Relic_LevelDes_31001010101` → 走 I18N#Relic

### 3.4 Skill 词缀被动（前缀 32）

**不配 I18N#Skill**——展示走 Affix.Describe。

例：中毒词缀
- 词缀 SkillID = `32000003xx` 系列，由 `Affix.SkillIDs` 数组挂载
- Affix.Name = `Affix_Name_3`、Affix.Describe = `Affix_Describe_3` → 走 I18N#Affix

### 3.5 Affix（词缀本体）

```
Affix.Name      → I18N#Affix.Affix_Name_{AffixID}
Affix.Describe  → I18N#Affix.Affix_Describe_{AffixID}
```

AffixID 通常 1-30 的整数（5 旧 + 25 新）。

### 3.6 Relic（圣物本体）

RelicID = 7 位（如 `4000101` = 部位 4 序号 001 件 01）。**注意 RelicID ≠ SkillID**。

```
RelicBase.Name      → I18N#Relic.Relic_Name_{RelicID}
RelicBase.RelicDes  → I18N#Relic.Relic_RelicDes_{RelicID}
RelicBase.IceDes    → I18N#Relic.Relic_IceDes_{RelicID}
RelicBase.FireDes   → I18N#Relic.Relic_FireDes_{RelicID}
RelicBase.Ice3Des   → I18N#Relic.Relic_Ice3Des_{RelicID}
RelicBase.Fire3Des  → I18N#Relic.Relic_Fire3Des_{RelicID}
RelicBase.Ice2Des   → I18N#Relic.Relic_Ice2Des_{RelicID}
RelicBase.Fire2Des  → I18N#Relic.Relic_Fire2Des_{RelicID}
```

### 3.7 RelicLevel（圣物等级效果）

```
RelicLevel.Effect       → Skill.SkillID（11 位）
RelicLevel.EffectDes    → I18N#Relic.Relic_LevelDes_{SkillID}（11 位 SkillID）
```

每级 1 个 SkillID，每级 1 条 I18N Key（不复用、不缩位）。等级描述按该等级实际收益写数值；如果效果由 Skill 添加 Buff 承载，需继续读对应 Buff 的属性、持续时间、叠加上限等展示值。

### 3.8 Inscription（铭文）

```
Inscription.PrimaryProfession#N.SkillID    → Skill.SkillID（铭文变体）
Inscription.PrimaryProfession#N.Name       → I18N#Inscription.Inscription_Name_{N}
Inscription.PrimaryProfession#N.Describe   → I18N#Inscription.Inscription_Des1_{N}
                                          / Inscription_Des2_{N} 等（4 阶逐阶累加）
```

同一铭文 4 阶（精良→传奇）共享 Name Key（不变）；Describe 按阶递增（Des1 / Des2 / Des3 / Des4），描述累加而不是顶替。

检查铭文展示时不要只看 `Skill.xlsx#Inscription`：该 sheet 负责铭文 ID、品质、图标、Name/Describe key 和挂载 SkillID；玩家实际看到的名称 / 描述正文在 `system/I18N.xlsx#I18N#Inscription`。如果任务明确要求暂不改 I18N，只检查并汇报差异，不回填正文。

检查铭文逻辑时也不要只看 SkillID：需要把 `Inscription.PrimaryProfession#N.SkillID` 的主动 / 被动组装结果，与对应铭文词条或铭文描述逐条对照。铭文词条写到但 SkillID 组装没有支撑，或 SkillID 实现了但词条没写清，都属于需确认。

改铭文名称或描述正文前，先反查同一个 `Inscription.Name / Describe` key 被哪些 `InscriptionBuildID` 引用。若不同铭文组共用同一 key，不要直接改 I18N 正文；先判断是主表引用串用，还是有意复用。同 key 串用但业务语义不同的情况，优先修 `Skill.xlsx#Inscription` 的 Name/Describe key 引用，再改对应 I18N 正文。

### 3.9 Buff

```
Buff.Name      → I18N#Buff
Buff.Describe  → I18N#Buff
```

Buff 文案 key 归属已确认是 `I18N#Buff`。如果检查时发现 `Buff.Name` / `Buff.Describe` 未命中 `I18N#Buff`，按 I18N 数据缺失、历史数据或热更覆盖继续核查，不改判到 `I18N#Skill`。

## 5. 孤儿 Key / 缺失 Key 检测方法

### 5.1 孤儿 Key（I18N 中存在但配表没引用）

```sql
-- 伪 SQL 思路：
-- 在 I18N#Skill 中存在 Key，但 Skill.xlsx 任何字段都没引用 → 孤儿
SELECT i.Key
FROM `system/I18N.xlsx#Skill` AS i
WHERE i.Key NOT IN (
  SELECT Skill.Name FROM `battle/Skill.xlsx#Skill`
  UNION
  SELECT Skill.Describe FROM `battle/Skill.xlsx#Skill`
  UNION
  SELECT Skill.Keyword FROM `battle/Skill.xlsx#Skill`
)
```

实操：用表格查询工具跑上述思路，或用项目通用审计脚本批量检查。

### 5.2 缺失 Key（配表引用了但 I18N 里不存在）

```sql
-- 配表里出现的 Key，但 I18N#Skill 没收录 → 缺失
SELECT Skill.Name, Skill.SkillID
FROM `battle/Skill.xlsx#Skill`
WHERE Skill.Name NOT IN (SELECT Key FROM `system/I18N.xlsx#Skill`)
  AND Skill.Name IS NOT NULL
```

### 5.3 配错 Sheet 检测（最易踩坑）

铭文变体技能（C≠0 或 D≠0）**配了 I18N#Skill** → 错配，应迁到 I18N#Inscription。

```sql
-- 找出 C≠0 或 D≠0 但 Name 仍指向 Skill_xxx Key 的行
SELECT SkillID, Name
FROM `battle/Skill.xlsx#Skill`
WHERE (SUBSTR(SkillID, 6, 1) != '0' OR SUBSTR(SkillID, 7, 1) != '0')
  AND Name LIKE 'Skill_%'
```

类似查圣物（前缀 31）和词缀（前缀 32）被动技能误配 I18N#Skill。

### 5.4 自动化建议

可维护一个项目通用 I18N 审计脚本，对每个战斗 sheet 跑：
1. 配错 sheet 检测
2. 孤儿 Key 检测
3. 缺失 Key 检测
4. Key 命名规则检测（不符合 `{System}_{Field}_{ID}` 规则的报警）

详见 `配表参考/约定/配表执行经验.md` 的配表前定位和产出后自检。
