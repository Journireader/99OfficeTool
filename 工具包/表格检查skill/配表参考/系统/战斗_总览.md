# 战斗系统总览

> 用途：从这里出发查 9 个战斗主题的任意一个。
> 术语：本文统一用 `配表参考/约定/战斗术语对照表.md` 选定的术语。
> 范围：战斗系统、AI、Skill、SkillDirector、词缀、圣物、铭文、Buff、通用战斗。
> 不重复内容：ECE 参数定义以飞书 `FF战斗字典备份` 为准；事件 / 条件实例以 `battle/BattleEvent.xlsx`、`battle/BattleCondition.xlsx` 为准，本文只画接入关系。

详细文字解释：

- **顶层 ECE 是字典**：Event/Condition/Effect 是三套枚举。它们由配表实例化（BattleEvent.xlsx / BattleCondition.xlsx 给出预定义实例；Skill 和 Buff 表自己写 TypeID/TypeData）。
- **主载体是 Skill**（行级 CastEventID）和 **Buff**（效果槽级 EventID）。两者共用同一套 ECE 枚举。
- **业务来源（词缀/圣物/铭文）通过 SkillIDs 组装**：4 个业务都不直接写 Effect，而是引用一组 SkillID。一个业务效果 = 多个 SkillID 串联。
- **AI 与 ECE 解耦**：AI（行为包/队列/执行策略）只输出"释放 SkillID 指令"。ECE 管线（Event/Condition/Effect）是战斗框架内部的事，AI 不订阅、不感知。AI 完整设计见飞书 AI 系统原文 `https://www.feishu.cn/docx/B1H1d7X0Fo0clax59r9cwaM4nRb`。

## 2. 9 主题速查（每主题 4 项）

每行：核心机制一句话 / ECE 接入方式 / 关联配表 / 关联文档。

### 2.1 战斗系统（顶层）

- **核心机制**：分动作层（操作 → SkillDirector → Trigger → 命中）→ 接口层（命中事件）→ 效果层（ECE）。
- **ECE 接入**：本身是管线定义者，不接入。
- **关联配表**：贯通全部 battle/ 表 + system/I18N.xlsx。
- **关联文档**：`配表参考/系统/战斗_ECE管线.md`、`配表参考/系统/战斗.md`、飞书战斗系统原文。

### 2.2 AI（怪物 + 主角）

- **核心机制**：怪物用"行为池 + 行为包 + 行为队列"；主角自动战斗按"普攻 2-5 段 > 爆发 > 核心类（历史设计称“怒气”） > 职业 > 普攻 1 段"释放。**AI 行为不再运行时按稀有度/玩法/强度计算**——所有 AI 参数（行为权重 / 行为包大小 / 走位偏好 / 仇恨系数 / 检测频率 / 踱步速度 / 预攻击触发器形状）行级直接读 `battle/MonsterAI.xlsx`；仇恨与检测频率默认值留在 `ConstComm`，行级填写则覆盖。`PacingSpeed=0` 表示怪物固定不动。
- **ECE 接入**：**与 ECE 完全解耦**。AI 只输出"释放 SkillID"指令，由 Skill 执行；不订阅 Event、不读 Condition、不写 Effect。
- **关联配表**：`battle/MonsterAI.xlsx`（当前正式源表，25 列，`AIId` 主键；详见 `配表参考/系统/战斗_MonsterAI.md`）、`battle/Enemy.xlsx`（`EnemyAI.Type=预攻击随机` 时 `EnemyAI.Value` 引用 `MonsterAI.AIId`）、`constant/Const.xlsx#ConstComm`（仇恨/检测频率默认值）、`battle/Skill.xlsx`、`battle/SkillDirector.xlsx`。
- **关联文档**：`配表参考/系统/战斗_MonsterAI.md`（配表执行：字段表 + 参数联动）、飞书 AI 系统原文（完整 AI 设计 + 运行逻辑）。

### 2.3 Skill / 技能

- **核心机制**：Skill 是"被动技能（ECE 组装器）"或"主动技能（玩家可释放）"的最小行单元；多 SkillID 组合成业务效果。
- **ECE 接入**：直接接入。`CastEventID` 是行级 Event；`Effects#N.{ConditionID, TypeID, TypeData}` 是效果槽。
- **关联配表**：`battle/Skill.xlsx`（Skill sheet，6 个效果槽）、`battle/SkillDirector.xlsx`、`system/I18N.xlsx#Skill`（仅基础版）。
- **关联文档**：`配表参考/系统/战斗.md`、`配表参考/系统/骑士技能.md`、`配表参考/系统/战斗_ECE管线.md`。

### 2.4 SkillDirector / 演出

- **核心机制**：动作层的关键帧编排——什么时候播什么动画、什么时间点生成哪个 Trigger、Trigger 对应哪些 SkillEffects。
- **ECE 接入**：SkillDirector 本身不接入 ECE，只在关键帧生成 Trigger，并通过 `LogicalTrigger#N.SkillEffects` 指向 Skill 效果槽。Skill 被动触发只认行级 `CastEventID`；`Skill.Effects#N.EventID` 是表头遗留字段，不作为触发点。
- **关联配表**：`battle/SkillDirector.xlsx`（8 个 Sheet：SkillDirector / Instant / Follow / Bullet / Trap / Throw / Summon / Ray Trigger）。
- **关联文档**：`配表参考/系统/战斗_Trigger类型.md`、飞书战斗系统原文。

### 2.5 词缀 / Affix

- **核心机制**：装备/装具的可叠加效果。一个词缀 = 一组被动 SkillID（前缀 32）。
- **ECE 接入**：通过 `Affix.SkillIDs` 数组挂被动 Skill；Skill 才接入 ECE。
- **关联配表**：`battle/Affix.xlsx`、`battle/Skill.xlsx`（被动技能）、`battle/Buff.xlsx`（配套 Buff）、`system/I18N.xlsx#Affix`。
- **关联文档**：`配表参考/系统/词缀圣物.md`。

### 2.6 圣物 / Relic

- **核心机制**：4 部位（誓印/战刃/项圈/鞭子，旧名"护符/枷锁/项圈/鞭子"）× N 件。当前 Relic 拆成本体、等级、星级、圣火祭坛和属性池。
- **ECE 接入**：`RelicLevel.Effect` 挂等级效果 Skill；`RelicBase.ThreeIceID/ThreeFireID/TwoIceID/TwoFireID` 挂套装效果 Skill；`RelicBase.IcePool/FirePool` 是属性池 ID，引用 `RelicPool.PoolID`，不是 SkillID。SkillID 前缀 31。
- **关联配表**：`battle/Relic.xlsx`（RelicBase / RelicLevel / RelicStar / RelicAltar / RelicPool）、`battle/Skill.xlsx`、`battle/Buff.xlsx`、`system/I18N.xlsx#Relic`。
- **关联文档**：`配表参考/系统/词缀圣物.md`、`配表参考/系统/战斗_RelicAltar.md`。

### 2.7 铭文 / Inscription

- **核心机制**：技能变体的品阶解锁。同一铭文 4 阶（精良→传奇）共享名称，描述逐阶累加，每升一阶解锁更多技能变体（C≠0 或 D≠0 的 SkillID）。
- **ECE 接入**：通过 `Inscription.PrimaryProfession#N.SkillID` 挂技能变体；变体 Skill 才接入 ECE。
- **关联配表**：`battle/Skill.xlsx`（Inscription / KnightInscriptionDevelop / WizardInscriptionDevelop / InscriptionAdvanced / InscriptionResonance / InscriptionAdvancedNeed / InscriptionTotolDraw 7 个 sheet）、`random/InscriptionRamdom.xlsx`、`role/Attribute.xlsx`、`system/I18N.xlsx#Inscription`。铭文属性 / 随机链先读 `事实卡/Inscription_Attribute_Random.md`。
- **关联文档**：`配表参考/系统/骑士技能.md`、`配表参考/系统/词缀圣物.md`。

### 2.8 Buff

- **核心机制**：持续效果载体。`BuffEffectType`（简称 BuffType）决定重复添加规则（护盾/属性增益/持续治疗/控制/属性减益/持续伤害）。当前 Buff 最多 5 个效果槽，每个效果槽可独立配置 Event。
- **ECE 接入**：直接接入。`Effects#N.EventID` 效果槽级 Event；`Effects#N.{ConditionID, TypeID, TypeData}` 效果槽。
- **关联配表**：`battle/Buff.xlsx`、`battle/BattleEvent.xlsx`、`battle/BattleCondition.xlsx`。
- **关联文档**：`配表参考/系统/战斗_ECE管线.md`、`配表参考/系统/战斗.md "Buff 表结构"`。

### 2.9 Director（行为指挥，归 AI 章节）

> 注：仓库内"Director"特指 SkillDirector（演出表），不是独立系统。AI 行为决策叫"行为包/行为队列"，**没有独立的 Director 表**。本主题指代等同 §2.4 SkillDirector 或 §2.2 AI 的"行为决策"层。

## 3. 跨表引用全景

```
Affix.SkillIDs (数组) ─────────────────┐
RelicBase.ThreeIceID/ThreeFireID/     │
TwoIceID/TwoFireID ───────────────────┤
RelicLevel.Effect ────────────────────┤
Inscription.PrimaryProfession#N.SkillID────→ Skill (中心枢纽)
                                                   │
            ┌───────── Skill 的字段引用 ───────────┤
            │                                       │
            ▼                                       ▼
   SkillDirectorID ─→ SkillDirector             CastEventID ─→ BattleEvent
            │                                       │
            ▼                                       ▼
   LogicalTrigger#N.{Type,TriggerID}    Effects#N.ConditionID ─→ BattleCondition
            │                                       │
            ▼                                       ▼
   InstantTrigger / FollowTrigger /     Effects#N.TypeID ─→ Effect 字典
   BulletTrigger / TrapTrigger /                   │
   ThrowTrigger / SummonTrigger /                  │ TypeID = 201 时
   RayTrigger                                      ▼
                                              Effects#N.TypeData[0] ─→ Buff
                                                                          │
                                                                          ▼
                                                    Buff.Effects#N.{EventID, ConditionID, TypeID, TypeData}
                                                    （递归回 Event/Condition/Effect/Buff）

I18N 引用：
   Skill.Name/Describe/Keyword ──→ I18N#Skill (基础版 C=0 D=0 才配)
   Affix.Name/Describe ──────────→ I18N#Affix
   RelicBase.Name/*Des ──────────→ I18N#Relic
   RelicLevel.EffectDes ─────────→ I18N#Relic
   Inscription.Name/Describe ────→ I18N#Inscription

圣物属性池：
   RelicBase.IcePool / FirePool ──→ RelicPool.PoolID
```

5 条主路径：
1. Affix→Skill（`Affix.SkillIDs` 数组）
2. Skill→SkillDirector（`Skill.SkillDirectorID`）
3. Skill→BattleEvent / BattleCondition（`CastEventID`、`Effects#N.ConditionID`）
4. Buff→BattleEvent / BattleCondition（`Effects#N.EventID`、`Effects#N.ConditionID`）
5. Relic→Skill（`RelicBase.ThreeIceID/ThreeFireID/TwoIceID/TwoFireID` 和 `RelicLevel.Effect`）；Relic→属性池（`RelicBase.IcePool/FirePool` → `RelicPool.PoolID`）

## 3.1 整体技能逻辑链条打印模板

当需要把一个技能、铭文、圣物、词缀或怪物技能的“配置如何串起来”打印成可读文档时，默认按整体逻辑链条输出，不只打印单表 ID。

推荐主表列：

| 模块 | 类型 | Director | 触发时机 | 条件 | 做什么 | 持续/CD |
|---|---|---|---|---|---|---|

字段口径：

- `模块`：用策划可读模块名。主动 / 被动优先取 Skill 备注或已整理的业务名；Buff 取 Buff 备注或可读名。
- `类型`：主动 / 被动 / Buff。
- `Director`：只打印主动技能的动作链路摘要；被动和 Buff 通常填 `-`。格式为 `Director {SkillDirectorID}`，下一行按 `trigger1/trigger2/...` 打印 `Trigger 类型 -> 效果序号`。
- `触发时机`：Skill / Buff 的 Event 口径，例如玩家释放、释放技能后、造成伤害后、Buff 自然移除后。
- `条件`：把 ConditionID 翻译成可读条件，并保留关键引用对象，例如“释放/触发的是哪个 Skill”“关联的是哪个 Buff”。不要只打印 `ConditionParams` 裸参数；例如 `Buff效果类型 20,1,100` 应打印为“目标持有护盾类 Buff”。
- `做什么`：只放真正执行的 Effect 结果，按 `1. 2. 3.` 分点；每点写成 `时间点：...；条件：...；效果：...`。其中 `时间点` 只写效果自身另配的时间点；没有单独配置时写 `无`，不要把外层 `触发时机` 复制进来。
- `持续/CD`：主动技能写 CD；Buff 写持续时间；两者都有时用 `；` 合并。

Director 列打印规则：

```text
1. Director 21430000001
2. trigger1：瞬时 -> 效果1
3. trigger2：子弹 -> 效果2、效果3、效果1
```

注意：

- `LogicalTrigger#N.SkillEffects` 中分号分隔的效果序号顺序就是实际释放顺序，必须按源表原始顺序打印，不能按 `效果1、效果2、效果3` 自动升序重排。
- 如果源表写 `SkillEffects = 2;3;1`，打印必须是 `效果2、效果3、效果1`。
- `做什么` 内的时间点要按对象分流：Skill 只读取行级 `CastEventID`，不要把 `Skill.Effects#N.EventID` 当触发点；Buff 才读取 `Effects#N.EventID`，空值表示 Buff 激活后立即执行。`Effects#N.ConditionID` 始终按条件解释，不当成时间点打印。
- 条件参数需要按枚举翻译：`Buff效果类型 100=护盾`，`200=属性类增益`，`300=持续治疗`，`400=控制/异常`，`500=属性类减益`，`600=持续伤害`；百分比类参数按万分比转百分比显示，例如 `9000=90%`、`500=5%`。
- Buff 备注或名称重复时，模块名必须补充 BuffID 做消歧，例如 `Buff：Buff_Name_100000013｜BuffID 213213001`，否则同名 Buff 的持续时间和效果容易串行。
- Director 列默认不打印 `LogicalTrigger#N.CreateTime`，除非任务明确要求分析帧点。
- Director 列默认不打印碰撞盒、弹道、外观、射程、动作等细节；这些属于调试版链路，可另起“Director 详情”或“Trigger 详情”。
- 如果 Director 引用了空效果槽，打印成 `效果N（源表未配置）`，不要静默丢弃，也不要脑补成其他效果。

最小链路来源：

```text
Skill / Buff
  -> Event / Condition / Effects
  -> Skill.SkillDirectorID
  -> SkillDirector.LogicalTrigger#N.Type + TriggerID
  -> LogicalTrigger#N.SkillEffects
  -> Skill.Effects#N（按 SkillEffects 原始顺序）
  -> Effect.TypeData 引用的 Buff / Skill / 条件对象
```

这套模板用于“理解技能怎么做出来”，不是源表回填模板；如果要调试碰撞盒或弹道，再下钻 `配表参考/系统/战斗_Trigger类型.md`。
