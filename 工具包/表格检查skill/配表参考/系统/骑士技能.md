# 骑士技能配表经验

## 规模

- 12 个主技能 × 13 个版本 = 156 版本
- 基础线：273 行（每版本 7 skill：起手 + 衔接 1-4 + 收招 + 平替）
- 核心（历史设计称“怒气”）/职业/爆发：各为单主动技能，117 行

## 铭文系统

一个铭文通过一组技能变体 ID 实现完整效果（每个品质阶段对应不同的 SkillID 组合）。

铭文表有两层引用不要搞混：
1. `SkillID` → 决定战斗逻辑（挂哪组技能变体，一个铭文对应多个 SkillID）
2. `Name / Describe` → 决定玩家看到什么（走 I18N#Inscription，不走 I18N#Skill）

同一铭文系 4 个品质行（精良→传奇）= 逐阶解锁机制，共享铭文名称，描述逐阶累加。每升一阶解锁更多技能变体。

- 4 阶逐阶解锁（1 阶 = 机制 1，4 阶 = 全部机制）
- I18N Key：`Inscription_Name_{N}` / `Inscription_Des1_{N}`

### 铭文装备口径（一个职业 4 个 BD 槽 × 单铭文 × 单调升档）

一名骑士同时只有 4 个铭文槽位：**基础 / 核心 / 职业 / 爆发**（与 `Inscription.BuildType` 1/2/3/4 一一对应）。每个槽位**只能装 1 个对应 BD 类型的铭文实例**，并且**品质升上去就不能下降**（精良 → 稀有 → 史诗 → 传奇 单调递增）。这条约束对铭文设计有两个直接含义：

- **同槽不要并联多铭文**：核心槽位只能选当前装的那一条（例：核心1 槽位上同时只有亚瑟 / 血月 / 刀锋 三选一），不存在"两条核心铭文同时生效"。因此跨铭文的协同要在描述上明确，不要假设玩家能同时叠两条同槽铭文。
- **高阶 SkillID 串必须自包含**：玩家从精良升到传奇之后，**只读传奇行的 SkillID 串**；不存在"传奇时还顺带挂载精良行"的回退路径。因此高阶不可省略低阶机制的承接（高阶要么沿用低阶主动 ID + 加新被动，要么换新主动 + 把要继承的低阶被动重新挂上），不要写"传奇默认继承精良数据"这种隐含话术。详见 [SkillID 与铭文的关系](#skillid-与铭文的关系) 和 [核心类铭文配置口径](#核心类铭文配置口径)。

### SkillID 与铭文的关系

- 基础版技能：C=0, D=0 → 配 I18N#Skill
- 铭文变体技能：C≠0 或 D≠0 → **不配 I18N**，玩家看到的是铭文描述

### 核心类铭文配置口径

核心类铭文通常是“主动替换 + 若干被动补逻辑”，不要把品阶继承理解成低阶 SkillID 全量累加。

- **高阶效果继承，不等于 SkillID 继承**：如果稀有/史诗只是把主动数值或公式升级，挂高阶主动即可，不要同时挂低阶主动，避免同一主动重复释放。
- **SkillID 字符串顺序要表达执行关系**：一般先写当前品阶主动，再写承接该主动的被动。多个被动监听同一事件时，按铭文 `SkillID` 字符串顺序执行。
- **被动条件要跟随实际主动版本**：主动从精良换到史诗后，命中后真伤、回血、叠层、击杀奖励等被动的 `CastConditionID` 要限定到当前实际主动；不要继续引用低阶主动条件，除非设计明确要同时监听低阶主动。
- **ComboSkillID 只在替换连招链时使用**：基础普攻链会通过 `ComboSkillID` 替换 1-7 段；核心技能当前多为单主动替换，通常只填 `SkillID`，不为了“看起来完整”补空的连招链。
- **三路来源不要偷合并**：流血 A/B/C、不同寄存 Buff、不同来源 Buff 如果在源表里分三条条件/效果，就按三路分别配；只有字典明确支持“任一来源 + 保留来源参数”时才合并。
- **重复添加 Buff 的结算要分前后监听**：如“目标已有强化放血时，本次重复添加触发结算”，先在 Buff 添加前打监听 Buff，再在 Buff 添加后按监听 Buff 结算并移除。不要只用“当前持有 Buff”判断重复添加。
- **前置增伤用标记闭环**：如果伤害前按层数加伤害结果，伤害前添加临时生效标记，伤害后按标记清层/清标记，避免未生效也清理或跨次残留。伤害结果提升用 `添加属性-1` 的属性 `119`，按当前 Buff 层数写 `119,5,1,单层系数`；不要误写成攻击 / 防御属性。
- **多段核心技能清层看 Director 末帧**：如果铭文要求“后续多段都吃增伤”，不要把清层挂到“核心技能释放后”这类释放事件。应在主动 `SkillDirector` 最后一段伤害之后补末帧 Trigger，关联清层效果，并给清层效果加“本次生效标记”条件，保证未命中或前置条件不满足时不误清。
- **不改核心技能时用消费窗口**：如果需求是“下一次核心技能整套多段都吃增伤”，但不希望改每个核心主动或 Director，可让增伤 Buff 监听“自身核心技能释放后”添加短倒计时窗口 Buff；伤害前仍按层数注入 `119,5,1,x`；窗口 Buff 自然移除后再清原 Buff。窗口时长要覆盖现有核心 Director 最长时长，并在备注写清。
- **改 Skill 效果必须同步查 Director**：骑士主动技能常由 `SkillDirector.LogicalTrigger#N.SkillEffects` 决定实际执行哪些效果。新增 Skill 效果槽、把清层并入主动、或调整效果顺序后，必须回查 Director 是否引用了新增效果序号，且时间点是否晚于目标伤害段。
- **自然移除触发范围效果**：护盾/窗口 Buff 结束后爆炸、反击、范围伤害等，监听 Buff 自然移除时间点；需要范围命中时，被动 Skill 也可以带 `SkillDirectorID` 生成 0ms Trigger。
- **后置判断不要改成前置增伤**：如果需求依赖“本次是否击倒/是否倒地/是否已有状态”的结果，放在攻击生效后追加等效伤害，不要强行放到伤害前。
- **隐藏需求要写进内部备注**：铭文描述只写 Buff 名或层数、但策划确认有隐藏数值机制时，不能按字面删链路。例：亚瑟传奇“掌声”除叠层外还承载每层 0.2% 直接类伤害结果提升和 50 层后 5% 当前伤害结果真伤；每层增伤用 `119,5,1,20`，50 层真伤应在直接类伤害后追加，并在备注标明“已确认隐藏需求”。

### 骑士铭文调平回填口径

- **初始技能与铭文默认保持一致**：装铭文后若描述没有明确写“提升 / 替换 / 追加”，基础连招伤害不要因品质自然递增。品质价值优先放到解锁机制、概率、条件、Buff 效果、冷却、消耗、控制或额外被动里。
- **核心 / 职业 / 爆发主伤先 base 化**：先按动作时间、技能消耗、触发频次、目标数和解锁修正得到基础主伤，再把品质增量拆成机制价值。不要只看表面倍率，也不要把同槽高阶 SkillID 串理解成低阶全部叠加。
- **描述锁定例外要同步配置和备注**：如果玩家可见描述写的是固定数值或固定机制（如流血 1/2/3、Trap 每几秒跳一次、某 Buff 的持续时间 / 上限），源表数值、I18N 和内部 Desc 备注必须同时对齐。内部备注不能继续保留旧倍率、旧持续时间或旧控制名，否则后续审表会按备注误判。
- **共享 Buff / 条件改动要先查反向引用**：Buff cap、持续时间、Condition 关系位这类支撑项可能被多个铭文复用。若只是某个铭文需要不同口径，优先新增专用 Condition / Buff，避免直接改共享项扩大影响面。
- **玩家可见 I18N 不写实现占位**：不要把“按配置寄存治疗”“按配置结算”等实现语塞进 `I18N#Inscription` 或 `I18N#Buff`。玩家文案应描述真实体验：触发时机、持续时间、每跳间隔、比例、上限和作用目标。

#### `Skill.CombatPower` 回填口径

- **只填玩家实际装配 Skill 的代表承载**：多个 Skill 组合成一个技能或连招时，只给代表 Skill 写战力；`ComboSkillID` 仅用于识别主动替换链，非代表连招段不额外填战力。
- **职业 / 圣物 / 共鸣按引用直填**：职业表引用的基础 / 核心 / 职业 / 爆发 Skill、圣物等级引用的 Skill、圣痕共鸣引用的 Skill 都按当前数值口径直接写 `CombatPower`。
- **当前数值锚点**：初始技能战力为基础 `4.89`、核心 `13.35`、职业 `1.99`、爆发 `10.25`；圣物等级为 Lv1 `2.06`、Lv2-10 每级 `0.11`；圣痕共鸣统一 `7.17`。
- **铭文品质值按增量理解**：铭文当前品质总战力 = 初始技能战力 + 已获得品质增量累计。不要把高品质行只当本品质增量，也不要把同一 SkillID 在多个品质行重复叠加。
- **当前铭文增量锚点**：精良 / 稀有 / 史诗 / 传奇分别为基础 `1.15 / 1.85 / 1.85 / 3.00`、核心 `10.78 / 17.43 / 17.43 / 28.21`、职业 `3.44 / 5.56 / 5.56 / 8.99`、爆发 `11.04 / 50.22 / 50.22 / 81.25`。
- **主动承载初始与继承值**：铭文品质行只统计 `PrimaryProfession#N.SkillID` 中的主动和核心被动；主动 Skill 承载初始技能战力。若高品质换了新主动，新主动继承上一主动已经承载的战力值。
- **核心被动承载本品质增量**：本品质新增的核心被动承载本档铭文增量；同品质新增多条被动时，按 `Inscription.SkillID` 字符串顺序选择首个新增被动，其余留空。
- **逐品质校验累计总值**：精良 = 初始 + 精良增量；稀有 = 初始 + 精良 + 稀有；史诗 = 初始 + 精良 + 稀有 + 史诗；传奇 = 初始 + 精良 + 稀有 + 史诗 + 传奇。当前品质行主动 + 已挂核心被动的 `CombatPower` 合计必须等于该累计总值。
- **冲突不强填**：若某品质没有新增被动且主动未替换，但累计目标增加，或同一 SkillID 在全局重复引用时推导出不同战力值，停止回填该铭文组并列冲突，不能为了凑总值重复写同一 SkillID。
