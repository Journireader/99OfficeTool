# 骑士时装配表经验

骑士时装配表完整参考。涵盖表结构、跨表串联、ID 规范、I18N 规则、踩坑记录。

---

## 一、表结构总览

时装系统的配置分布在 4 个 xlsx 文件、7 个 Adornment sheet 中；当前 workbook / sheet 边界见 `约定/全表快照.md`（2026-08-21 / r5020）：

```
develop/Adornment.xlsx          （7 个 sheet，主业务 sheet: AdornmentSkin）
  ├─ AdornmentSkin      ← 皮肤（肤色，17 行）
  ├─ AdornmentHair      ← 发型
  ├─ AdornmentFace      ← 表情
  ├─ AdornmentClothes   ← 时装外观本体（主键：AdornmentClothesID）
  ├─ FashionStar        ← 升星配置（主键：FashionID = ItemID）
  ├─ FashionLevel       ← 升级配置（主键：FashionID = ItemID）
  └─ FashionSuit        ← 套装配置（主键：FashionID = FashionSuitID）

system/Item.xlsx
  └─ Item               ← 时装道具（主键：ItemID）

system/I18N.xlsx
  ├─ I18N#AdornmentClothes  ← 时装名称文案
  ├─ I18N#Item              ← 道具名称/描述文案
  └─ I18N#Fashion           ← 套装名称文案

system/Condition.xlsx
  └─ Condition           ← 时装解锁条件
```

## 二、跨表串联关系

```
                    ┌──── FashionStar.FashionID ────┐
                    │                                │
AdornmentClothes ──(ItemID)── Item ──(ItemID)── FashionLevel.FashionID
       │                       │
       │                       └──── Condition.Value1（解锁条件引用 ItemID）
       │
       └── SuitID ──── FashionSuit.FashionID（套装维度，不是道具维度）
```

### 关键串联规则

1. **AdornmentClothes ↔ Item**：通过 ItemID 关联。普通时装当前配置习惯通常是 `AdornmentClothesID = ItemID`；如果投放道具和外观本体分离，则以道具 `ItemID` 为准。

2. **FashionStar / FashionLevel 的 FashionID = ItemID**。普通时装当前配置习惯常见为 `AdornmentClothesID = ItemID = FashionID`，但不要把该习惯当成必然关联键；投放道具和外观本体分离时按 `ItemID/FashionID` 串联。

3. **FashionSuit 的 FashionID = FashionSuitID**（1001~1004, 2001~2012），跟道具/装扮 ID 完全不同。

4. **Condition 的关联方式**：`ConditionID` 格式为 `GC_AdornmentClothes_Fashion_{ItemID}`，`Value1` 存储 ItemID。AdornmentClothes 的 `UnlockCondID` 字段引用这个 ConditionID；`UnlockCondID` 为空时按默认解锁处理。

5. **I18N 各管各的**：
   - AdornmentClothes.NameID → `AdornmentClothes_NameID_{ACID}`（在 I18N#AdornmentClothes）
   - Item.Name → `Item_Name_{ItemID}`（在 I18N#Item）
   - Item.Describe → `Item_Describe_{ItemID}`（在 I18N#Item）
   - FashionSuit.NameID → `FashionSuit_NameID_{FashionSuitID}`（在 I18N#Fashion）

6. **名称显示口径**：
   - `I18N#AdornmentClothes` 是外观本体名，不加 `时装·` 前缀，例如 `鬼角盔`。
   - `I18N#Item` 的时装道具名需要加 `时装·` 前缀，例如 `时装·鬼角盔`。
   - `I18N#Item` 的时装道具描述写清套装归属和升星收益，格式建议：`{套装名}部件。获得后解锁「{道具名}」外观；升星后可提升属性。`
   - `I18N#Fashion` 的套装名不加 `时装·` 前缀，例如 `炎角鬼武套装`、`粗糙装备套装`。

7. **激活与套装生效**：
   - 未激活时装时，客户端按 `FashionStar` 的 `Star=1` 行读取激活消耗和首星属性；`FashionLevel` 的首级属性也会参与未激活预览。
   - 套装按 `SuitID` 聚合部件；任一部件未拥有时套装星级视为 0，全部拥有后取所有部件当前星级的最小值作为套装生效星级。

## 三、两种时装来源

### 装备幻化（保留 EquipID 关联）

- `AdornmentClothesID = EquipID`（5位），`ItemID = 603XXYY`（7位）
- 共 44 件（11 品质 × 4 部位）
- 品质：01=粗糙, 02=普通, 03=精良, 04=稀有, 05=史诗, 06=传奇, 07=神话, 08=无暇, 09=暗金, 10=绝艺, 11=元祖, 12=不朽（预留）
- 外观名称跟 Equip 保持一致（不加 `时装·` 前缀）；对应道具名称在 I18N#Item 加 `时装·` 前缀
- **不参与 6TTSSQP 编码**

### 独立套装（TT=02）+ 散件（TT=00）

- 4 套 × 4 部位 × 2 阶级 = 最多 32 件（当前 24 件）
- 散件 3 件
- 遵循 `6TTSSQP` 编码

## 四、ID 编码规范 `6TTSSQP`（7 位）

法师（巫师）独立时装使用职业专用前缀 `605`，格式为 `605SSQP`：SS=资源套装号（03/04），Q=1基础、2进阶，P=1武器、2头部、3胸部、4酒壶。套装003使用 `6050311–6050314` / `6050321–6050324`，套装004使用 `6050411–6050414` / `6050421–6050424`；分别关联 FashionSuitID 3003/3004，HeroResID 3003/3103、3004/3104。下述既有 `6TTSSQP` 投放点规则继续用于原骑士时装，法师 `605` 不按投放点05解释。

| 段 | 位数 | 含义 | 范围 |
|---|---|---|---|
| 6 | 1 | 时装前缀 | 固定 |
| TT | 2 | 投放点 | 00=散件, 02=独立套装 |
| SS | 2 | 套装序号 | 01~99 |
| Q | 1 | 阶级 | 0=无, 1=基础, 2=升级 |
| P | 1 | 部位 | 1=武器, 2=头部, 3=胸部, 4=酒壶 |

套装序号：01=野人甲(1001), 02=野人乙(1002), 03=剑圣(1003), 04=风男(1004)

示例：`6020311` = 02(独立套装) + 03(剑圣) + 1(基础) + 1(武器)

## 五、各表字段速查

### AdornmentClothes
AdornmentClothesID / Desc备注 / NameID / PrimaryProfessionType / QualityType / PartType / SuitID / IconID / HangingPoint.Type / HangingPoint.Data / UnlockCondID / UnlockReward.PropType / UnlockReward.Value

### FashionStar
FashionID(=ItemID) / NameID / PrimaryProfessionType / QualityType / PartType / SuitID / IconID / Star(1-3) / ExpendNum / StarAttr#1.Type+Data / StarAttr#2.Type+Data / PassiveCondition / PassiveLimit / PassiveAttr#1.Type+Data

`Star=1` 行同时承担时装激活行：未激活预览、激活消耗和首星属性都从这里取。

`PassiveCondition / PassiveLimit / PassiveAttr` 是 r5008 新增结构，但当前 proto 与非生成消费者尚未定义，属于程序前置；在程序补齐前不要把这些列与已生效的 `StarAttr` 合并描述。

### FashionLevel
FashionID(=ItemID) / NeedStar / Level / Expend_PropType+PropID+Value / LevelAttr#1.Type+Data / LevelAttr#2.Type+Data

**时装进阶不需要进阶道具。**

### FashionSuit
FashionID(=FashionSuitID) / NameID / PrimaryProfessionType / ResID / PictureID / QualityType / Star / SuitAttr#1.Type+Data / SuitAttr#2.Type+Data

### Condition
ConditionID(`GC_AdornmentClothes_Fashion_{ItemID}`) / ConditionItems_1_Value1(=ItemID) / ConditionParams(星级)

## 六、踩坑记录

1. **FashionStar/Level 的 FashionID 语义是 ItemID** — 普通时装可以沿用 `AdornmentClothesID = ItemID = FashionID` 的配置习惯，但改外观本体或投放道具 ID 时最容易漏这两个表
2. **装备幻化行有公式** — NameID 列是 `="AdornmentClothes_NameID_"&A14`，openpyxl 不带 data_only 读到的是公式
3. **FashionStar/Level 也有公式行** — 如 `=A3+10`，遍历时需 try/except
4. **旧套装 ItemID ≠ ACID** — 套装3的 ACID=6100031 但 ItemID=6110011（"冲刺"投放），套装4的 ItemID=6120011（"战令"投放）
5. **不朽品质数据不一致** — Condition 有预留，AdornmentClothes/Item 暂无
6. **所有表双行表头** — 第1行中文描述，第2行英文字段名，数据从第3行开始
7. **套装星级取短板** — 不是按最高星或任意部件星级生效；全部部件拥有后才取最低星级作为套装星级。
8. **Passive 列当前不可只配表生效** — Excel 结构已存在，但 proto / 消费者未闭合；正式填值前先完成程序前置并验证条件、上限和属性聚合。
