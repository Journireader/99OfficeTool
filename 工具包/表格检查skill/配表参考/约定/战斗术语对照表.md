## 2. 命名注意事项（弃用术语别再写进新文档）

### 2.1 Buff 相关

- 看到旧文档中"异常状态" → 在新文档里统一写 "Buff（BuffEffectType=400 控制类）"，因为"异常状态"既可能指 Buff 也可能指状态机的"战斗·异常"定位（见 HeroState/MonsterState）——两个东西。
- 不要再在新文档里写"EffectType"指代 Buff 字段。Buff.xlsx 字段是 `BuffEffectType`，可简称 BuffType。

### 2.2 Event 相关

- 字典中的"时间点类型"是字段中文释义，**不要把它当术语写**。术语是 Event。
- Skill.Effects.EventID 字段在 SDK 中**保留但未生效**（详见 配表参考/系统/战斗_ECE管线.md §2.4）——配表只在行级 CastEventID 配 Event。

### 2.3 Skill 相关

- "Skill 表的一行"≠"玩家看到的一个技能"。玩家看到的是基础版技能（C=0 D=0）；多个 Skill 行通过铭文/词缀/圣物组装才构成完整业务效果。
- 描述铭文时用"铭文变体技能"，不要叫"铭文 Skill"——后者会与 Inscription 表本身（Skill.xlsx 内的 Inscription sheet）混淆。

### 2.4 圣物相关

- 历史资料中的"护符/枷锁"是早期命名，battle/Relic.xlsx 已迁到"誓印/战刃/项圈/鞭子"。新文档一律用新名；旧名只在引用历史资料时保留并加注 `(旧名"护符"，现表名为"誓印")`。
- 旧/新名映射：**誓印 = 护符（旧）、战刃 = 枷锁（旧）、项圈不变、鞭子不变**
- RelicID 是 7 位（`4000101`），SkillID 是 11 位（`31001011101`）——不要混。

### 2.5 Trigger 相关

- "点击类/子弹类/蓄力类"是**手感分类**（玩家如何输入），SkillDirector.xlsx 的 8 个 Sheet 是**实现分类**（Trigger 的生命周期/运动方式）。两者**不是一回事**——同一个技能可能既是"长按蓄力类"（玩家手感），又生成 BulletTrigger（实现）。新文档要分清场景用哪套。
- 攻击碰撞盒分两类：**预攻击 Trigger**（PreAttackTrigger，AI 用于检测能否攻击）vs **逻辑 Trigger**（LogicalTrigger，关键帧瞬时生成做命中判定）。两个东西，不要简称为"Trigger"。

### 2.6 AI 相关（新增 V2 修正）

- AI 与 ECE 是**解耦的**：AI 只输出"释放 SkillID 指令"，不订阅 Event、不读 Condition、不写 Effect。
- 不要写"AI-Event 对接"措辞——这暗示存在衔接，违背设计本意。AI 通过释放 SkillID 后由战斗框架自行处理 Event/Condition/Effect 链。

## 3. 术语决策记录

| 决策点 | 选项 | 选定 | 决策依据 |
|---|---|---|---|
| Buff vs 状态 | (a) 全用"状态" / (b) 全用"Buff" / (c) 按层次分（持续效果用 Buff，状态机定位用"状态"） | **(c)** | 状态机本身就是个概念（HeroState/MonsterState），叫"战斗·异常"等定位；与 Buff 是两层。统一名一刀切会混淆 |
| BuffEffectType / BuffType vs EffectType | (a) 全用 EffectType（兼容旧文档）/ (b) 字段写 BuffEffectType，说明中可简称 BuffType / (c) 泛指叫 EffectType | **(b)** | 源表字段为 BuffEffectType；EffectType 名字让位给 Effect 枚举 |
| 圣物部位旧名/新名 | (a) 沿用规则文档"护符/枷锁" / (b) 改用配表"誓印/战刃" / (c) 双轨并列 | **(b)** + 同步 ID编码规范.md（已于 2026-04-29 完成） | 配表是产物，规则是描述。配表先动了，规则文档应该跟上 |
| Trigger 分类维度 | (a) 用"点击类/子弹类/蓄力类"3 类 / (b) 用 SkillDirector 8 sheet 的实现名 / (c) 拆"手感/实现"两套 | **(c)** | 两套各有用，强行统一会丢信息。战斗_Trigger类型.md 详细分维度展开 |
| "演出表"叫 SkillDirector 还是"导演表" | 中文化 vs 表名 | **SkillDirector**（中文写"演出/动作编排"做注释） | 表名稳定，中文短语随场景写 |
| AI 与 ECE 关系（V2 修正） | (a) 写"AI-Event 对接" / (b) 写"AI 与 ECE 解耦" | **(b)** | AI 只输出 SkillID 指令，剩下战斗框架内部消化 Event/Condition/Effect。"对接"措辞误导 |
