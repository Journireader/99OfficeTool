# 索引链检查

本文用于沉淀跨系统字段联查和自动检查规则。它不替代源 Excel，只规定“看到某类字段时先往哪条链路查、哪些字段不能当全局外键、哪些结论必须保留服务端边界”。

## 适用范围

- 默认适用于 `/Users/Shared/FF配置表/策划/数据表/develop` 当前正式表链。
- 不存在于当前 `develop/` 的历史目录、备份目录和已删除目录，不参与当前索引链检查、缺口统计或源表回填。
- 链路检查和数据质量检查分开：链路确认不代表当前每个 key / ID 都已补齐；未命中项先列为缺失或需确认，不直接推翻链路。
- 遇到占位值、历史保留值、未启用运营档位，先标“需确认”，不要直接判错。

## 一、检查分类

### 1. 直接外键链

这些字段可以作为自动检查的第一批强链路：

| 字段 | 目标 |
|---|---|
| `PictureID` / `*PictureID` / `IconPath` / `BackgroundImageID` | `system/Picture.xlsx#Picture.PictureID` |
| `AudioID` | `system/Audio.xlsx#Audio.AudioID` |
| `WindowID` | `system/Window.xlsx#Window.WindowID` |
| `PurchaseID` | `commerce/PurchaseList.xlsx#PurchaseList.PurchaseID` |
| `SkillID` / `SkillIDs` | `battle/Skill.xlsx#Skill.SkillID` |
| `EnemyID` | `battle/Enemy.xlsx#Enemy.EnemyId` |

检查时先排除 `0`、空值、`暂无`、废弃目录和明确历史保留值。分号列表要拆分后逐项检查。

### 2. 前缀分流链

| 字段形态 | 目标 |
|---|---|
| `GC_*` 条件 key | `system/Condition.xlsx#Condition.ConditionID` |
| `BC_*` 条件 key | `battle/BattleCondition.xlsx#BattleCondition.ConditionID` |
| `Event_*` 战斗事件 key | `battle/BattleEvent.xlsx#BattleEvent.ID` |

其它前缀先查所在系统文档和代码，不直接归类。

### 3. 上下文分流链

以下字段名不能当全局外键：

- `PropID`：必须同组读取 `PropType`，再按资源、道具、装备、圣物、时装等系统分流。
- `ResID`：必须结合字段全名、所在 workbook / sheet 判断；战斗实体资源和活动 UI 资源不是同一条链。
- `TypeID`：必须结合所在结构判断；`Skill.Effects#N.TypeID` 和 `Buff.Effects#N.TypeID` 走 `NEW_EFFECT_TYPE`，业务表 `TypeID` 多为本表类型或运营分组。

## 二、已确认通用链路

### 1. 奖励三元组

奖励常见字段：

```text
Loot / Reward / Product / Item#N
-> PropType + PropID + Value
-> 按 PropType 分流到 Resource / Item / Equip / Relic / Fashion 等系统
```

- `Value` 是数量。
- `PropID > 0` 时优先使用 `PropID`。
- `PropID` 为空或 0 且 `PropType < PROP_TYPE_ITEM(200)` 时，客户端会用 `PropType` 补成资源类 `PropID`。
- 客户端可确认展示和解析；实际发奖、背包落包、重复领取校验仍以服务端为准。

### 2. I18N 统一链

```text
任意 I18N# 开头 sheet
-> I18NConfig.Key / Lang#N
-> 客户端合并为 key -> lang content
-> i18n.t(key)
```

典型字段：

- `Buff.Name / Describe -> I18N#Buff`
- `Enemy.Name -> I18N#Enemy`
- `Skill.Name / Keyword / Describe -> I18N#Skill`
- `Questionnaire.Desc -> I18N#Questionnaire`
- `Resource.Name / Describe -> I18N#Resource`

`I18N.xlsx` 不是一张固定语言表，而是按业务拆成多个 `I18N#` sheet；新增文案先判断归属 sheet，再补 key。

### 3. 资源表现链

```text
PictureID / IconPath / BackgroundImageID
-> Picture.PictureID
-> Picture.FileName
-> 按 UI 场景拼资源路径
```

```text
AudioID
-> Audio.AudioID
-> WinType / Path / Volume
```

```text
WindowID
-> Window.WindowID
```

```text
AnimationID
-> Anime.AnimeID
-> AnimeDirector / AnimeReport
```

```text
SpecialEffectID
-> SpecialEffectID
-> SpinePath / PathType / AnimationName / HangingPointType / Offset
```

`ResID` 不属于这条通用表现链。战斗实体类 `ResID` 需要按上下文查 `RoleRes.xlsx` 对应 sheet。

### 4. 怪物资源链

```text
battle/Enemy.xlsx#Enemy.ResId
-> role/RoleRes.xlsx#MonsterRes.MonsterResID
-> MonsterRes.MonsterModelID
-> role/NudeModel.xlsx#MonsterModel.MonsterModelID
-> MonsterModel.SpinePath
```

`MonsterRes.HangingPoint#N.Data` 与 `MonsterModel.HangingPoint#N.Data` 指向 `role/EquipModel.xlsx#MonsterEquipModel`，不是 `system/Resource.xlsx`。

### 5. 技能 / Buff 效果链

```text
Skill.Effects#N.TypeID
-> proto NEW_EFFECT_TYPE
-> EffectService / EffectHandlerRegistry
```

```text
Buff.Effects#N.TypeID
-> proto NEW_EFFECT_TYPE
-> BuffEffect / EffectHandlerRegistry
```

`SkillDirector.LogicalTrigger#N.SkillEffects` 是 1-based 效果下标，决定执行 `Skill.Effects#N` 中哪些效果，不改变 `Effects.TypeID` 的含义。

### 6. 系统事件 / 公告链

表格引用链：

```text
Prompt.xlsx#PromptSystem.SystemEventID
-> SystemEvent.xlsx#SystemEvent.SystemEventID
```

客户端系统聊天显示链：

```text
服务端聊天消息 extData.SystemPromptID
-> PromptSystem.SystemPromptID
-> PromptSystem.DataID
-> I18N 富文本
-> 聊天系统显示
```

客户端当前不按 `SystemEventID` 主动触发、过滤或广播；系统公告触发规则需要服务端确认。

## 三、玩法链路边界

### 1. ActivitySchedule

```text
ActivitySchedule.ActSchedID
-> 服务端下发 ActivityInfo.ActSchedID / ActConfigID / ActType
-> ActivityFactory 按 ActType 分发
-> 具体活动模块按 ActConfigID 查自己的业务表和 reward 表
```

`ActivitySchedule` 是活动实例与排期入口，不直接承载奖励；活动展示、参与条件、活动状态过滤需要保留服务端边界。

### 2. PurchaseList

```text
业务表 PurchaseID
-> PurchaseList.PurchaseID
-> PurchasePropType / PriceInCent
-> 创建订单请求 PurchaseID + SceneType
-> 服务端发货回包 Reward
```

`PurchaseList` 是 SKU 和价格表，不是奖励表。奖励或商品内容在 `Store`、`LimitPackage`、`PromoPack`、`StarterPack`、`TargetRush` 等业务表的 `Product / Loots / Reward` 字段里。

### 3. Dungeon / WorldHunting / Adventure

- `Dungeon.xlsx` 是副本入口目录，不是通用战斗关卡框架。
- 冒险 / 世界狩猎中，客户端可确认入口展示、进入战斗和回包后的房间 / 怪物拼装。
- 房间随机、掉落实例生成、掉落池权重、Boss 状态、占领奖励仍需要服务端确认。

### 4. Questionnaire

```text
Questionnaire.Sid
-> AladinSDK.getSurveyInfo / navigateToSurvey
-> QuestionnaireRewardReq(Sid)
```

- `Questionnaire.Desc -> I18N#Questionnaire`
- `Questionnaire.UnlockCondID -> Condition.ConditionID`
- `Questionnaire.Reward#N(PropType, PropID, Value)` 用于客户端预览

问卷页面、外链映射和实际领奖权威不在本地表，必须保留服务端或外部系统边界。

## 四、自动检查优先级

建议脚本先实现：

1. 直接外键完整性检查。
2. `PropType + PropID + Value` 三元组合法性检查。
3. `GC_* / BC_* / Event_*` 前缀分流检查。
4. `Enemy.ResId` 怪物资源链检查。
5. `Skill.Effects#N.TypeID` / `Buff.Effects#N.TypeID` 枚举可识别检查。
6. I18N key 命中检查，按业务 sheet 分组输出缺失。

输出缺口时分三类：

- `缺失`：当前正式表链应命中但未命中。
- `需确认`：历史保留、占位值、未启用运营档位、服务端权威字段。
- `不检查`：历史 / 已删除目录、备注、排序字段、价格数值、明确非外键字段。
