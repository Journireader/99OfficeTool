跨系统字段联查、自动外键检查、服务端边界和 `PropID` / `ResID` / `TypeID` 分流规则，先读 `约定/索引链检查.md`。本文件负责说明具体 workbook / sheet / 字段形态。

当前全量快照见 `约定/全表快照.md`；本文件只保留字段级精讲、主业务 sheet 识别和已确认字段语义。字段级精讲见 "三"~"六" 节（已详细抽样的核心表）。两者互补：快照用于快速定位，精讲用于深入理解。

## 一、先记住的结构规律

当前已抽样确认的核心表，绝大多数都符合下面这套读法：

1. 默认第 2 行是字段行。
2. 默认第 3 行开始是数据行。
3. 字段里大量使用“嵌套对象 / 数组展开”命名。

常见命名形态：

- `Reward.PropType`
- `ConditionItems#1.ConditionType`
- `Effects#1.TargetType`
- `Loots#1.PropID`
- `TaskItemConfig.Targets#1.TaskType`
- `SrvMatch.ValidRange`

后续看到这类字段名时，默认按“结构化对象被平铺到列”理解，不要误判成普通文本字段。

### 2. 隐含关系读法

很多关系不靠字段名直接写成外键，而靠配置习惯表达：

- 分号列表：`SkillID`、`TaskID`、`AdventureAreaID`、`AdventureBarrierID` 这类字段可能一格填多个 ID，先按列表拆，再逐项反查。
- 同 ID 多行：随机池、箱子、时装升星 / 升级、活动礼包档位常用同一个业务 ID 重复多行组成完整配置。
- ID 家族：房间、礼包、活动、道具、时装、黑猎人技巧等常按号段或公式组织。看见相近 ID 时先判断是否是同一族，不要只查单行。
- `GC_*` 条件键：这类值通常是条件或系统逻辑键，不是最终文案，也不是普通字符串。
- 文案键：`NameID`、`DescriptionID`、`Describe`、`LanguageKey` 多数不是中文本体，要继续查 `I18N.xlsx` 对应业务 sheet。
- 入口链：`SystemFunctionID`、`WindowID`、`JumpID` 分别管功能语义、窗口展示和跳转，不要互相替代。
- 支付链：`ActivityID` / `ActCfgID`、`PackID`、`PurchaseID`、`GroupID`、`BindID` 分层不同，不能因为数值相近就当成同一键。
- 覆盖值：带“覆盖 DB 数据”说明的养成字段按覆盖结果读，不是增量。
- 通用外键链：`PictureID` / `IconPath` / `BackgroundImageID` 查 `system/Picture.xlsx#Picture`；`AudioID` 查 `system/Audio.xlsx#Audio`；`WindowID` 查 `system/Window.xlsx#Window`；`PurchaseID` 查 `commerce/PurchaseList.xlsx#PurchaseList`。
- 历史目录：不存在于当前 `develop/` 的历史目录或已删除目录，不作为正式回填目标，也不纳入默认索引链缺口统计。

做配置前先判断目标字段属于哪种隐含关系，再决定是按单行、按同 ID 分组、按分号列表，还是按跨表链路检查。

## 三、通用支撑表结构

### 1. `system/I18N.xlsx`

结构定位：

- 不是“一张文案表”，而是“按业务拆 sheet 的文案工作簿”
- 每个业务 sheet 结构接近

已确认 sheet 示例：

- `I18N#Skill`
- `I18N#Equip`
- `I18N#Item`
- `I18N#SystemFunction`
- `I18N#Enemy`
- `I18N#Task`
- `I18N#TermLink`

已确认字段形态，以 `I18N#Skill` 为例：

- `Key`
- `Lang#1.Name`
- `Lang#1.Val`
- `Lang#2.Name`
- `Lang#2.Val`

理解方式：

- `Key` 是文案键本体
- `Lang#n.Name` 是语言标识，如 `zh-cn`
- `Lang#n.Val` 是对应文案内容

结论：

- 后续如果新增名称、描述、关键词、提示，不能只记“补 I18N”
- 还要先判断它落在哪个业务 sheet
- 运行时会从配置 MD5 表中动态加入所有 `I18N#` 开头的配置 key；本索引列出的 sheet 是常用归属入口，不是唯一运行加载名单。
- I18N 富文本中的 `<link>TermLinkID</link>` 指向 `system/TermLink.xlsx#TermLink`，用于点击词条后显示 tips；词条名称和描述通过 `I18N#TermLink` 承接。

- `SpinePath` / `PathType` / `AnimationName` 定位特效资源和播放动画。
- `HangingPointType` 与 `Offset.X` / `Offset.Y` 决定挂点和全局偏移。
- `DontStop` 是死亡不清除开关：`1` 表示死亡不清除，`0` 表示死亡清除。

结论：

- 表现链引用特效时不能只查资源路径，还要确认挂点、偏移和死亡清除策略。
- 角色动作、模型、技能表现等链路引用 `SpecialEffectID` 时，先回到本表确认特效实际挂接方式。
