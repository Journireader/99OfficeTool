# 配表速查表

一页纸覆盖高频规则。agent 接到配表任务时先读本页，再按表名进入 `约定/表到专题索引.md` 和命中的 `事实卡/*.md`。细节以原文档为准：`约定/ID编码规范.md`、`约定/产出规范.md`、`约定/配表执行经验.md`、`约定/索引链检查.md`、`系统/*.md`。

**主从关系**：本表与原文档冲突时，以原文档为准。涉及单系统深度规则（骑士技能铭文双层、词缀套装效果、时装跨表等），仍需读对应 `系统/*.md` 深度文档。

---

## Agent 首轮入口

```text
任务关键词 / 表名 / ID
  -> 本速查表压缩风险
  -> 约定/表到专题索引.md 找第一参考和事实卡
  -> 事实卡/*.md 看字段语义、反向影响、验收清单
  -> 源 Excel 当前行读回
  -> 需要字段级细节时再读 约定/表字段索引.md
```

按输入类型分流：

| 用户只给了... | 先做什么 | 不能直接做什么 |
|---|---|---|
| 系统 / 玩法名 | 先从本页命中任务类型，再去 `表到专题索引` 找主表和事实卡 | 不要全量扫 `develop/` |
| 表名 / sheet 名 | 先查 `表到专题索引` 的第一参考、事实卡和状态 | 不要跳过系统专题直接写表 |
| 字段名 / ID / key | 先读事实卡和 `索引链检查` 判断是主键、外键、枚举还是上下文分流字段 | 不要凭字段名当全局外键 |
| 一段业务描述 | 先拆成主表、支撑表、承接表、表现表四类 | 不要只改看起来最像的一张表 |
| 现有配置截图 / 行号 | 先回源 Excel 读当前行和相邻行，再判断引用链 | 不要按截图或旧行号直接修改 |

## ID 前缀（SkillID 11 位 / 时装 7 位）

| 类型 | 前缀 | 说明 |
|------|------|------|
| 怪物 Skill | `10xx` / `11xx` | |
| 骑士 Skill | `21` + 线路(1-4) + 系别(1-3) + 变体(0-3) + 阶(0-4) + 序号(5位) | 各线路范围内序号唯一 |
| 巫师 Skill | `22xx` | |
| 猎人 Skill | `23xx` | |
| 圣物 Skill | `31` + `0` + 部位(PP) + 序号(RR) + 类型(TT) + 技能组(GG) | 部位 01 誓印 / 02 战刃 / 03 项圈 / 04 鞭子 |
| 词缀 Skill | `32` + `00000` + 序号(AA) + 技能组(GG) | 被动范围 30001-30999（词缀）/ 31001-31999（圣物） |
| 时装 | `6` + 投放点(TT) + 套装(SS) + 阶级(Q) + 部位(P) | 7 位；部位 1 武器/2 头/3 胸/4 酒壶 |
| ItemID（时装映射） | `603` + EquipID 后 4 位 | |

**产出前必查当前最大 ID**：以最新 ID 分配记录和目标源表现有最大值为准。

## 三条运行链

| 需求 | 最短链 |
|---|---|
| 配商业化活动 / 礼包 | `ActivitySchedule -> ActivityInfo -> reward 业务表 -> PurchaseList -> Loot/Item/AutoPopup` |
| 配冒险关卡怪 | `AdventureBarrier -> Weak/StrongEnemyRoom -> Enemy -> EnemyAttrGrow + MonsterRes + MonsterAI/Skill` |
| 配副本玩法 | `Dungeon -> SystemFunction/Window -> 具体玩法主表 -> Scene/Enemy -> Reward/Item/Random` |
| 配养成系统 | `主养成表 -> Attribute -> Item/Random/Condition/I18N/Skill -> 角色属性聚合` |
| 配幻灵系统 | `Pet -> PetSkill/成长/天赋/图鉴 -> PetRamdom/PetDream -> Skill/Attribute/Item/Scene` |
| 配魂石系统 | `SoulStone -> StoneSet/强化/重铸/炼魂/突破/图鉴 -> Skill/Attribute/Item/I18N`；`ProfessionType/StoneSetSkillParamScale` 当前需程序前置 |
| 配魂石副本 | `SoulStoneDungeonBoss -> Room + 周一~周日 DropRule -> Scene/Enemy/Condition/SoulStone` |
| 配军团活动 | `GuildTrial 或 UltimateGuilds -> 区分客户端展示与服务端结算状态 -> Boss/任务/排名/奖励/活动排期` |
| 配世界 Boss | `WorldBoss -> 题库/答题奖励/BuffRandom/伤害奖励/排名奖励 -> Scene/Enemy/Buff/Prompt` |
| 配入口 / 解锁 | `SystemFunction -> Condition -> Prompt/I18N -> Window/Jump/Guide` |

细节读 `约定/配表链路运行模型.md`，不要只凭主表下结论。

## 战斗审表三步

1. 先串 `Skill → Director → Trigger → Effect`，看执行顺序和哪一帧生效。
2. 再核 `Condition / Buff`，确认是谁在判、谁在承载窗口或计数。
3. 最后回到字典逐位看 `TypeData / EventData / ConditionParams`，不要用相邻行猜参数。

最常见的三条链路直接先套：

- `BUFF移除前 + Buff编号_时间点 + Buff编号+Buff层数`：最后一击未命中 / 自然结束检查。
- `最后一击 / 第 N 段命中`：挂对应 `LogicalTrigger`，不要拿整次技能释放后的被动时间点去猜。
- `铭文独立主动 + 条件 retarget`：精良单拎主动后，相关被动条件要跟着新主动走。

## xlsx 产出硬规则（5 条）

1. **整表副本**：复制源表所有 sheet/数据/结构，原有数据不动
2. **黄底黑字下划线**：本次新增或修改的单元格统一标记
3. **枚举值格式**：`[枚举类型名]枚举值名`（如 `[新效果类型]物理伤害-1`、`[Buff效果类型]护盾`）
4. **不准填 xxx / test**：数据要有实际游戏意义
5. **备注列不留空**：每行 Desc备注 列（column_2）必填

## 写入边界

- 评审副本：复制完整 workbook，本次新增或修改单元格标记为黄底黑字下划线。
- 正式源表回填：不带评审标记，只写最终值，保留原样式、公式、富文本和无关 sheet。
- 格式敏感源表：优先最小范围 value / XML 补丁，不做整 workbook round-trip。
- Excel 修复弹窗：验收失败，必须从干净基线重做。

## 完成后 4 类自检（漏项 8 坑）

产出后按类过一遍：

| 类别 | 查什么 |
|------|--------|
| 文案 | I18N Key 补齐、Prompt 提示反馈补齐 |
| 接入 | Condition 解锁条件、SystemFunction/Guide/Jump 入口跳转 |
| 结算 | Event/SystemEvent 触发、Item 奖励承接 |
| 资源 | 引用的图/音频/特效/窗口对应资源表补齐 |

主键/外键/编号规则变化时，**必须扫所有引用表**。

## 结构决策原则（spec 未明确时）

- 会继续扩展 → 数组字段
- 固定只有 1 个值 → 普通字段
- 强关联外部主表 → ID 引用
- 没明确要重构 → 优先兼容旧字段
- 参数风格优先沿用源表已有风格
