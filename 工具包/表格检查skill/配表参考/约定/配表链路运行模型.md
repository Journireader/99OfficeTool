# 配表链路运行模型

## 1. 用途

这份文档回答“整条配表链路怎么运转”。它不是字段索引，也不替代源 Excel；它用于在需求进入具体字段前，先判断主表、支撑表、承接表、表现表和代码运行边界。

## 2. 通用四层

```text
主表：定义业务规则
  -> 支撑表：定义开放、条件、入口、触发、跳转
  -> 承接表：定义奖励、物品、商店、随机池、背包
  -> 表现表：定义玩家看到的文案、图标、资源、窗口、动画
```

配表时先问 6 件事：

1. 主表是哪张，主键或分组键是什么。
2. 是否需要活动开放窗口、功能解锁、条件或触发事件。
3. 是否有奖励、道具、箱子、随机池或商店承接。
4. 是否新增玩家可见文案、提示或富文本。
5. 是否引用图片、音频、动作、特效、场景或窗口。
6. 哪一段由客户端或服务端运行时解释，不能靠表名推断。

## 3. 五条高频运行链

### 3.1 商业化活动链

```text
commerce/ActivitySchedule.xlsx
  -> ActivitySchedule.ActType + ActConfigID + StartTime/EndTime/ShowTime
  -> ActivityInfo.ActType + ActConfigID
  -> reward 业务表 ActCfgID / ActivityID
  -> PurchaseID -> commerce/PurchaseList.xlsx
  -> Loots / Reward / Product -> Item / Chest / Random / Resource
  -> I18N / Prompt / Picture / AutoPopup / SystemFunction
```

关键点：

- `ActivitySchedule` 管开放窗口，`ActivityInfo` 管入口展示，reward 表管内容。
- `ConditionID` 不是活动私有逻辑，服务端走公共 `Condition`。
- `PurchaseID` 是支付 SKU，不等于 `PackID`、`GroupID`、`StageID`。
- 自动弹窗是附加入口，按 `PopupType` 或 `TriggerEvent + Params` 命中。

### 3.2 冒险关卡怪链

```text
AdventureChapter
  -> AdventureArea
  -> AdventureBarrier
  -> AdventureWeakEnemyRoom / AdventureStrongEnemyRoom
  -> SceneID + EnemyID / BossData / HelperData
  -> Enemy
  -> EnemyAttrGrow + MonsterRes + Skill + MonsterAI
  -> SkillDirector / Trigger / Effect
```

关键点：

- 问“配冒险关卡的怪”时，不能只改 `AdventureBarrier`。
- 小怪房按 `EnemyNumPlans` 决定每波数量，再从每波 `EnemyID / PosID` 池抽取。
- Boss 房用 `BossData / HelperData` 明确点位和 EnemyID。
- 怪物等级由 `Enemy.Level.Type` 决定，跟随关卡等级时必须有对应 `EnemyAttrGrow`。
- `Enemy.EnemyAI.Type` 决定是否读取 `MonsterAI`，技能效果仍走 Skill 链。

### 3.3 入口与条件链

```text
SystemFunction.SystemFunctionID
  -> UnlockCondID -> Condition
  -> PromptID / I18N
  -> Window / Jump / Guide
  -> 业务模块入口或按钮
```

关键点：

- 空 `UnlockCondID` 通常表示不设门槛。
- `Condition` 的 `SubConditionIDs`、`ConditionItems` 和文案提示要分开理解。
- 客户端锁定提示会尝试找第一个未满足的子条件作为提示来源。
- `Window` 管界面，`Jump` 管跳转，`SystemFunction` 管功能开放语义。

### 3.4 副本玩法链

```text
Dungeon
  -> SystemFunction / Window / Jump
  -> 具体玩法主表：Adventure / WorldHunting / PiggyDungeon / NewBieDungeon / BloodSearch / Arena
  -> Scene + Enemy / NPC / Room / Waves
  -> EnemyAttrGrow + MonsterAI + Skill
  -> Reward / Loot / Item / Random / Mail
```

关键点：

- `Dungeon` 多数时候是入口聚合，不是具体关卡或波次表。
- 副本玩法要先判断具体玩法主表，再查场景、怪物、奖励和入口。
- Piggy / NewBie / BloodSearch 直接有 `EnemyData / BossData / NpcData` 这类字符串解析字段。
- Arena 是赛制链：全局配置、段位、奖励、积分差、战令分表维护。

### 3.5 养成系统链

```text
职业 / 装备 / 装备格 / 时装 / 圣物 / 黑猎人
  -> Attribute
  -> Skill / Condition
  -> Item / Random / Store / Reward
  -> I18N / Picture / Resource / Model / AVG
  -> 角色属性聚合模块
```

关键点：

- 养成不是单表链，先判断是哪条主链。
- 装备、时装、圣物、黑猎人都会把属性并入角色属性，但入口表、ID 规则和承接表完全不同。
- `Attribute` 是属性语义事实源，`Item / Random / Reward` 是获得和消耗承接，`I18N / Picture / Model` 是表现承接。
- 系统内前置 ID 不一定是公共 Condition，例如 `HunterTalent.ConditionID` 实际是前置技巧配置 ID。

## 4. 定位规则

| 用户输入 | 定位方式 | 输出应该包含 |
|---|---|---|
| 玩法名 | 先找系统专题，再找事实卡 | 主表、支撑表、承接表、表现表 |
| 表名 / sheet | 查 `表到专题索引` | 第一参考、事实卡、状态 |
| 字段名 / ID | 查事实卡和 `索引链检查` | 字段语义、目标表、反查范围 |
| “新增一个礼包/活动” | 先走商业化活动链 | ActivitySchedule、ActivityInfo、业务表、PurchaseList、奖励、弹窗 |
| “配关卡怪” | 先走冒险关卡怪链 | Room、Enemy、EnemyAttrGrow、MonsterAI、Skill、Scene |
| “配副本/竞技场/寻血/金猪” | 先走副本玩法链 | Dungeon 入口、具体玩法主表、Scene、Enemy、Reward、SystemFunction |
| “配装备/时装/圣物/黑猎人/职业” | 先走养成系统链 | 主表、Attribute、Item/Random、Condition、I18N、Skill |
| “入口打不开/未解锁” | 先走入口与条件链 | SystemFunction、Condition、Prompt、Window/Jump |

## 5. 回补规则

如果一次任务发现下面任一类新事实，必须回补到配表参考：

- 字段语义或参数顺序变化。
- `@cfg:map/group/list/groupmap/struct` 读取规则变化。
- 跨表引用或反向引用变化。
- 客户端/服务端解释方式变化。
- 玩家可见文案、I18N、Prompt 展示口径变化。
- AI 配表提示词或 RAG 检索路径需要新增事实卡。

回补优先级：

1. 能快速裁决的稳定事实，写 `事实卡/*.md`。
2. 系统内的完整链路和配置经验，写 `系统/*.md`。
3. 跨系统通用规则，写 `约定/*.md`。
4. 入口变化同步 `README.md`、`约定/速查表.md`、`约定/表到专题索引.md`。
